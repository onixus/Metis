# AGENTS.md — рабочая инструкция агента-разработчика Метиды

Метида (Metis) — платформа портфельного управления продуктами. Полное ТЗ: [docs/spec.md](docs/spec.md).
Этот файл — раздел 7 ТЗ в форме инструкции. Агент реализует этап 1 по разделам 2–5 ТЗ.

## Стек

| Слой | Выбор |
| --- | --- |
| Бэкенд | Go (текущая стабильная), net/http, chi, pgx v5, sqlc, oapi-codegen, log/slog, OpenTelemetry |
| Граф | gonum/graph в памяти, рёбра в PostgreSQL |
| БД | PostgreSQL 16, схема на модуль, pgvector, миграции goose |
| Очереди | Outbox и воркер на PostgreSQL (`SKIP LOCKED`) |
| Аналитика | Материализованные представления (этап 1) |

| Фронтенд | TypeScript, React, Vite, TanStack Query, клиент из OpenAPI, React Flow |
| Идентификация | OIDC (go-oidc); Keycloak на стенде |
| Поставка | Статические бинарники (`CGO_ENABLED=0`), Docker, Helm, docker compose |

## Архитектурные инварианты

Нарушение любого пункта — дефект, даже если тесты зелёные.

1. Модуль обращается к другому только через публичный интерфейс или доменные события. Запросы к таблицам чужой схемы запрещены (depguard, каталоги `internal/`).
2. Домен не зависит от chi, pgx, sqlc-кода и HTTP-клиентов. Зависимости направлены внутрь.
3. Каждая сущность несёт `product_id`. Методы репозиториев принимают обязательный `authz.Scope`; он создаётся только пакетом `identityaccess`; нулевое значение запрещает всё.
4. Поля, которыми владеет внешняя система, доступны только на чтение.
5. Любая запись во внешнюю систему идёт через outbox.
6. Деньги — `int64` в минорных единицах и код валюты. `float32`/`float64` для денег запрещены; аллокация — в decimal.
7. Время в БД — UTC. Плановые даты — тип «дата» без времени.
8. Журналы аудита и доказательств — только `INSERT`. `hash = SHA-256(prev_hash || canonical_json(record))`. Роль приложения не имеет `UPDATE`/`DELETE` на эти таблицы.
9. Без `unsafe` и cgo. Без `panic` вне `main` и тестов. Ошибки обёрнуты через `%w`, проверяются через `errors.Is`/`errors.As`.
10. `context.Context` — первый параметр каждой операции ввода-вывода. Глобального изменяемого состояния нет.
11. Секретов нет в коде, конфигурации, фикстурах и логах.
12. LLM-контуры — отдельные бинарники; `cmd/external-research` не импортирует пакеты с доступом к БД и индексам (depguard).

## Правила работы

- Перед итерацией прочитать требования по ID и записать план в `docs/plans/NN.md`. Код без плана не начинать.
- На каждое требование — минимум один тест с ID в имени: `TestPG05_RejectsFeatureCycle`.
- Изменение API начинается с `api/openapi.yaml`; сгенерированный код вручную не правится.
- Решение, которого нет в ТЗ, — сначала ADR в `docs/adr` (MADR).
- Неоднозначность не додумывать: вопрос в `docs/questions.md`, наименее необратимый вариант, `TODO(question-NN)` в коде.
- Новая зависимость — только с ADR: назначение, лицензия, сопровождение. Допустимые лицензии: MIT, Apache-2.0, BSD, ISC, Zlib; MPL-2.0 — по ADR.
- Применённые миграции не изменять; только новые.
- Шаги безопасности в CI и линтеры не отключать. `//nolint` — только с причиной и записью в `docs/questions.md`.
- Упавший тест — чинить причину. `t.Skip` без записи в `docs/questions.md` запрещён.
- Реальные данные, токены, имена клиентов не использовать. Фикстуры синтетические.
- Сеть — только реестры пакетов.
- Conventional Commits. Один pull request на итерацию: что сделано, какие ID закрыты, как проверить, что не сделано.
- Чужой код — только как зависимость с проверенной лицензией. Копирование фрагментов запрещено.
- Каждый PR указывает, какие части написаны агентом и кто из людей их проверил (основание NF-L01).
- Ядро не содержит кода, специфичного для Jira или Confluence; сценарий приёмки проходит с выключенными адаптерами Atlassian.

- [ ] Каждая новая ABAC-политика имеет тест на отказ
- [ ] `api/openapi.yaml` обновлён; серверные интерфейсы и клиент перегенерированы
- [ ] Миграции обратно совместимы на один релиз
- [ ] govulncheck, go-licenses, gitleaks без находок либо исключение в ADR
