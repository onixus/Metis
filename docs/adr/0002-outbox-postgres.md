# ADR-0002. Outbox и очередь на PostgreSQL

Статус: принято · Дата: 2026-09-17

## Контекст

ТЗ 7.1: брокер добавляется только при невыполнении NF-P03…P05. Все записи во внешние системы идут через outbox (инвариант 5), потеря события исключена (NF-R06).

## Решение

Таблица `kernel.outbox` в той же транзакции, что и доменная запись. Воркер `cmd/worker` выбирает записи `FOR UPDATE SKIP LOCKED`, доставляет обработчику по типу, при ошибке увеличивает `attempts` и назначает `next_attempt_at` с экспоненциальной задержкой; после `max_attempts` запись переходит в `kernel.outbox_dlq`. Доменные события для внутренних подписчиков идут тем же механизмом.

## Последствия

Один компонент состояния (PostgreSQL), RPO задаётся архивацией WAL. Пропускная способность ограничена; при нарушении NF-P03…P05 — отдельный ADR о брокере.
