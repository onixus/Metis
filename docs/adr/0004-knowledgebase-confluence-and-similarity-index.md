# ADR-0004. Порт KnowledgeBase, адаптер Confluence и индекс похожести на этапе 2

Статус: принято · Дата: 2026-09-17

## Контекст

Этап 2 (ТЗ раздел 6) требует адаптер Confluence, создание страниц discovery brief и ADR из шаблонов (DS-05, DA-01) и подсказки похожих сигналов (SG-04). Векторный индекс с моделью эмбеддингов и версионированием (AI-10) относится к этапу 5. Ядро не должно содержать кода, специфичного для Confluence (ТЗ 7.5).

## Решение

1. Порт `ports.KnowledgeBase` нейтрален к системе: страница, шаблон, метки, свойства, текст для индекса. Адаптер `adapters/confluence` работает с REST API Confluence Data Center (`/rest/api/content`, `/property`, `/label`, поиск по CQL). Запись страницы выполняется только из обработчика outbox (`decisions.PublishPageHandler`), инвариант 5. Тела страниц рендерятся чистыми функциями пакета `knowledgedocs` (MADR для ADR, discovery brief) в storage-разметке с экранированием.
2. Стенд: мок Confluence на WireMock (`deploy/compose/confluence-mock`) по образцу мока Jira; сценарий приёмки проходит с выключенным адаптером (NF-L03).
3. SG-04 на этапе 2 реализуется интерфейсом `discovery.SimilarityIndex` с двумя реализациями без модели эмбеддингов: TF-IDF с косинусной мерой в памяти и полнотекстовый поиск PostgreSQL (`tsvector`, конфигурация `russian`). Векторная реализация на pgvector добавляется на этапе 5 за тем же интерфейсом, когда появится профиль эмбеддингов (AI-09, AI-10).

## Рассмотренные варианты

- Вызов Confluence напрямую из `decisions` — нарушает инварианты 1 и 5, отвергнуто.
- pgvector с фиксированной моделью эмбеддингов уже на этапе 2 — потребовал бы LLM-gateway и переиндексацию при смене модели (AI-10); отложено.
- Хранение текста страниц в платформе — вне границ системы (документы остаются в Confluence, ТЗ 1.1).

## Последствия

Новых зависимостей нет: адаптер на `net/http`, индекс на стандартной библиотеке. Точность подсказок похожести до этапа 5 ограничена лексическим сходством; это отмечено в `docs/questions.md`.
