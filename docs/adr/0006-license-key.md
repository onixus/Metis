# ADR-0006. Лицензионный ключ поставки (AD-06)

Статус: принято · Дата: 2026-09-18

## Контекст

AD-06 требует ключ со сроком действия и лимитами, проверяемый без доступа в интернет.
Платформа ставится в закрытом контуре заказчика, поэтому обращение к серверу лицензий исключено.
Ключ не должен позволять заказчику продлевать срок и поднимать лимиты самостоятельно, но и не должен
останавливать работу при расхождении часов или в день истечения.

## Рассмотренные варианты

| Вариант | Оценка |
| --- | --- |
| Подписанный офлайн-ключ (Ed25519, стандартная библиотека) | Проверка без сети и без внешних зависимостей; приватный ключ остаётся у поставщика |
| HMAC на общем секрете | Секрет попадает в поставку — заказчик может выпустить себе ключ |
| Онлайн-активация | Противоречит требованию «без доступа в интернет» |
| Аппаратный ключ | Дороже поставки и сопровождения, не требуется ТЗ |

## Решение

Ключ — строка `metis-1.<base64url(payload)>.<base64url(signature)>`. `payload` — канонический JSON
(`kernel.CanonicalJSON`) с полями: идентификатор лицензии, заказчик, издание, дата выпуска,
`not_before`, `not_after`, лимиты (`products`, `users`) и перечень включённых модулей.
Подпись — Ed25519 (`crypto/ed25519` стандартной библиотеки) по каноническому представлению payload.
Публичный ключ поставщика вшит в бинарник; приватный ключ в репозитории отсутствует (правило
«секретов нет в коде»). Для стенда и тестов пара ключей генерируется на лету.

Проверка выполняется при старте и при операциях, ограниченных лимитами (создание продукта,
выдача доступа пользователю). Истёкший ключ не останавливает чтение: платформа переходит в режим
только для чтения по операциям, попадающим под лимиты, и сообщает об истечении. Льготный период —
30 дней после `not_after`, в течение которого запись разрешена, но каждое такое действие пишется в аудит.
Расхождение часов компенсируется допуском в 24 часа для `not_before`.

## Последствия

Новых зависимостей нет. Отзыв выданного ключа невозможен без сети — компенсируется коротким сроком
действия ключа. Смена пары ключей — только с выпуском новой версии платформы; поэтому проверка
принимает список публичных ключей, чтобы старые лицензии работали на один релиз вперёд.
