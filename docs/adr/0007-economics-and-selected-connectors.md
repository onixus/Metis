# ADR-0007: версионируемая экономика и выбранные источники

Дата: 2026-09-22. Статус: принято для пилота. Требования: EC-01…13, NF-S02/14/15/16, DL-05, AD-05, ТЗ 4.1/4.2.

## Контекст

Экономического модуля нет. Владелец выбрал Jira, Confluence, Bitrix и 1С. Конфигурация 1С, пользовательские поля CRM, версии установок и корпоративные правила аллокации пока не заданы. Расчёт не должен изменять прошлый период при обновлении файла или формулы.

## Решение

Ввести economics с неизменяемыми версиями месячного финансового снимка: владеющий продукт, валюта, исходные строки и lineage, правила распределения, определения полей и формул, дата/автор, закрытие. Append использует ожидаемую версию; явный пересчёт закрытого периода создаёт новую версию. Участники межпродуктовой аллокации проверяются по Scope. Суммы — int64 minor units, доли — decimal; остатки распределяются детерминированно с сохранением общей суммы, переполнение и смешение валют отклоняются. Сценарии используют тот же вычислитель без записи фактов.

Исходные финансовые данные и детальные отчёты доступны только роли finance с finance=full и доступом к каждому участвующему продукту. Это консервативная стартовая политика, исключающая восстановление ФОТ малой команды через разность итогов. Автоматический импорт использует отдельный явно созданный сервисный Scope. Расширение доступа aggregates требует отдельной модели подавления связанных итогов. Каждое чтение/экспорт и изменение аудируется без финансовых значений в журнале ошибок.

Finance — порт разбора переданных байтов CSV/XLSX с явным маппингом. ZIP/XML/CSV разбираются stdlib с лимитами, без макросов, внешних связей и исполнения формул; сохраняются только cached values. Ошибка любой строки запрещает частичную фиксацию. Новая зависимость не нужна. Настраиваемые формулы ограничены размером и DAG, без исполнения произвольного кода.

Bitrix трактуется как Bitrix24 REST CRM. Для 1С поддерживается стандартное чтение OData v3 либо экспорт CSV/XLSX. Коллекция, поля, валюта и сопоставление продуктов задаются явно; конфигурационные имена не угадываются. Адаптеры read-only, ограничивают страницы/ответы, не передают авторизацию на другой origin и не возвращают секреты/исходные значения в ошибках. Jira и Confluence сохраняют текущие Data Center контракты; provider factory находится в инфраструктуре, домен использует порты.

Публикация Confluence получает стабильный ключ решения и повторяемое оформление labels/properties. Поиск страницы по стабильной идентичности восстанавливает результат после потери ответа; без серверного idempotency key это reconciliation, а не гарантия exactly-once. Все внешние записи выполняет outbox.

## Альтернативы и последствия

- Изменяемые строки и формулы дешевле, но уничтожают воспроизводимость закрытого периода.
- Универсальное исполнение формул XLSX/скриптов запрещено NF-S14/15.
- Готовый XLSX SDK добавляет зависимость и большую поверхность; ограниченный табличный импорт покрывается stdlib.
- Автоматическое угадывание полей 1С/CRM создаёт правдоподобные неверные финансовые результаты; вместо этого требуется маппинг и preview.

Ограниченный расчётный DAG пересчитывается целиком; incremental caching и безопасные агрегаты для нефинансовых ролей остаются отдельной работой. Контрактные тесты не заменяют приёмку на конкретных конфигурациях заказчика.
