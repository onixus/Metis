# ADR-0013: двусторонняя трассировка DecisionRecord

Статус: принято. Дата: 2026-10-10. Issue: #25.

## Контекст

Discovery обходит четыре типа источников, добавляет решения как листья и отвергает decision как корень. Web запрещает такой маршрут. DecisionRecord уже хранит связи, но обратный порт отсутствует; при обходе insight текущий адаптер передаёт в decisions неподдерживаемый kind.

## Решение

Расширить публичный порт discovery.DecisionLinks чтением решения и ссылок трассировки. App адаптирует decisions.Get; полномочия сохраняются. Не расширять типы ссылок DecisionRecord: commitment/release/track остаются вне цепочки DS-04, insight достигается через гипотезу/сигнал. Решение раскрывается с его настоящим product_id; связанные приватные сущности проверяются своим модулем.

Один visited применяется ко всем видам, включая решения и невидимые источники. Предел — 256 разрешённых попыток чтения узлов и 1024 ребра (вопрос 47), плюс отмена контекста. Ответ добавляет необязательные incomplete/truncated: недоступные и удалённые источники не раскрывают ID, названия, продукт или причину отказа. Невидимый корень возвращает обычный отказ, без частичного графа; сбои инфраструктуры не маскируются как отсутствие источника.

При первом превышении предела весь обход останавливается: уже собранный граф возвращается с truncated, очередь больше не раскрывается. Отмена проверяется и на повторных связях, и перед выдачей результата; отменённый запрос не возвращает успешный граф.

Web допускает корень decision и смену корня через каждый узел, сохраняя обычные ссылки карточек. Все изменения API добавляемые; старые клиенты продолжают читать nodes/edges. Новых библиотек нет.

## Последствия

Обе стороны показывают один и тот же доступный компонент графа; порядок зависит от корня. Большой компонент явно помечается ограниченным. Стратегический читатель может видеть разрешённое решение/фичу, но не приватные источники. Предел не является нагрузочным SLO и требует отдельной настройки после измерений.
