# ADR-0018: явное сохранение правил при повторном импорте

## Статус

Принято для итерации 24.

## Контекст

EC-07 требует версии повторных загрузок; ручной импорт книги сейчас заменяет строки вместе с правилами. Номер строки XLSX и hash документа меняются при исправлении или сортировке и не являются устойчивой идентичностью.

## Решение

Оставить обычный импорт совместимым. Добавить отдельный явный режим сохранения правил. Бизнес-ключ состоит из продукта, статьи, команды, фичи, трека, ветки, бандла, описания и имени/листа источника. Сумма, headcount, номер строки и hash в ключ не входят. Ключ должен быть уникальным в обеих версиях; неоднозначность запрещает весь импорт. Для совпавшей строки сохраняются ID, аллокации и ручные значения; внешние факты всегда берутся из нового доверенного preview. Удаление строки с ручными значениями или аллокациями запрещается, чтобы изменение файла не уничтожало настройки неявно. Оператор может выбрать обычный импорт со сбросом правил.

## Последствия

Перестановка строк и изменение суммы/численности не теряют настройки; изменение описания или источника требует явного пересмотра. Нет эвристического переноса правил между разными сущностями. История и проверка expected_version остаются неизменяемыми. Новых зависимостей и миграций нет. Полная произвольная ручная карта соответствий не реализуется.
