# ADR-0021: Доступные действия жизненного цикла релиза

- Статус: принято
- Дата: 2026-10-25
- Требования: RM-04, RM-05, CM-05; план 25

## Контекст

API уже поддерживает состояния planned, ready_for_certification, released и eol. UI позволял редактировать атрибуты и запросить готовность, но не выпускать релиз или снимать его с поддержки. Создание релиза с ready_for_certification обходило проверку гейтов, тогда как обновление запрещало такой переход. API снятия EOL существовал, но кнопка UI была отключена для пустой даты.

## Решение

Предоставить в редакторе существующие состояния planned, released и eol. Готовность к сертификации устанавливать только отдельной командой с проверкой гейтов, включая запрет ready_for_certification при создании. При редактировании уже готового релиза его статус можно сохранить. Смена ветки выпущенного или снятого с поддержки релиза остаётся запрещённой существующим доменным правилом. UI блокирует эту смену заранее.

Разрешить только движение вперёд: planned → ready_for_certification / released, ready_for_certification → released, released → eol. Сохранение того же статуса разрешено. Обратные переходы запрещены: иначе возврат в planned позволял изменить ветку уже выпущенного релиза, нарушая RM-04. Переход в ready_for_certification всегда выполняется отдельной командой. ТЗ не определяет обязательную сертификацию для любого релиза, поэтому planned → released разрешён. Полный процесс согласования выпуска требует отдельного решения владельца. Очистка EOL выполняется существующей отдельной командой с `eol: null`; обычное обновление с опущенным EOL сохраняет его.

## Последствия

Nullable-EOL требует явного ключа `eol`: `{}` и JSON `null` вместо объекта не снимают дату поддержки. Собственный transport-тип `httpapi/request.ReleaseEOLInput` проверяет наличие ключа при JSON-декодировании; обычный указатель на дату не отличал бы отсутствие поля от явного null. OpenAPI задаёт этот Go-тип через `x-go-type`; сгенерированные адаптеры не правятся вручную. Валидные дата и `{"eol":null}` сохраняют совместимость.

Пользователь может завершить жизненный цикл через интерфейс. Нет новых зависимостей, таблиц или внешних записей. OpenAPI принимает nullable дату в команде EOL: JSON `null` снимает её; пустая строка остаётся недопустимой датой. Отказ создания с готовностью проверяется до записи и публикации события. Доменный контроль статуса, ветки и ABAC остаётся обязательным независимо от UI. Замораживание состава, release notes или плановой даты после выпуска здесь не вводится: ТЗ не задаёт такого ограничения, а данные могут исправляться владельцем.
