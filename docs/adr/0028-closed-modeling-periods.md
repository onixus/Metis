# ADR-0028: определения и доли не изменяют закрытый период

## Статус

Принято для итерации 24, EC-02/EC-04/EC-11/EC-12.

## Контекст

Modeling выбирает определения и правила по дате действия при чтении. Простое закрытие периода блокировало импорт и Recalculate без force, но ретроспективная версия поля/формулы/аллокации/бандла либо новые доли команды меняли результат обычного чтения закрытого периода без явного пересчёта.

## Решение

До записи любого определения или правила отклонять effective_from, действующую хотя бы на один закрытый период: нулевая дата включена, допустимая дата строго позже конца самого позднего закрытого периода. Это распространяется на первые версии новых ключей: нулевой effective_from означает «всегда» и потому тоже ретроспективен. Проверять нормализованную фактическую дату, чтобы последующие версии без явно заданной даты могли действовать с текущего дня, если он позже закрытых периодов.

Ручные и worklog доли команды запрещено заменять в закрытом периоде. Проверки и запись используют одну существующую транзакцию PostgreSQL с application lock, как и ClosePeriod; никакого force для правил/долей нет. Явный force-импорт данных и существующий явный Recalculate остаются отдельными действиями. API возвращает ErrConflict с объяснением и границей допустимой даты.

## Последствия

Обычные чтения Value/PnL сохраняют закрытый результат при попытках изменения определений/долей. Новые будущие версии разрешены и сохраняют историю. Ретроспективное изменение определений закрытого периода требует будущей реализации атомарного снимка результатов/явного переоткрытия; эта итерация такой обход не имитирует. Memory-хранилище остаётся для локальных тестов, межоперационная PostgreSQL-сериализация подтверждается отдельно integration gate.
