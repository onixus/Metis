# ADR-0030: типизированные прямые источники формул

Статус: принято для итерации 28, EC-09/10/13.

Функции `worklogs()`, `crm_revenue()`, `headcount()` читают один scoped snapshot активного среза. Worklogs выражены в секундах, выручка — в целых минорных единицах валюты модели, численность — в неотрицательном числе людей. Двухаргументный вариант (`worklogs("product", "*")`) заменяет одно измерение: имя и значение должны быть строковыми константами, как в агрегатах полей. Срез всегда включает конкретный календарный месяц: wildcard периода запрещён. Item не поддерживается для источников, не имеющих данной оси, и должен быть явно отклонён адаптером.

Доменный `PlatformSources` принимает context, Scope, тип источника и срез; адаптеры читают только публичные порты модулей. Engine не знает HTTP/pgx и не выполняет произвольные сетевые/пользовательские запросы. Отсутствующий, устаревший, неполный или неразрешённый источник возвращает ошибку; нулевой агрегат допустим лишь с непустыми snapshot ID/временем и provenance источника. Не возвращаются индивидуальные зарплаты и авторы worklogs.

Один расчёт запоминает snapshot каждого source+slice, включая вложенные метрики. Исполняемые обращения входят в Explain с provenance и временем; неисполненные ветки не читают источник. CEL RefSource обеспечивает граф зависимостей и выборочный пересчёт. Внешние факты книги изолированы, но те же явно подключённые публичные источники доступны формуле. Формулы ссылаются на источник явно; при закрытых периодах адаптер обязан возвращать устойчивые исторические снимки, иначе расчёт закрытого источника должен быть отклонён.

Ограничения числа обращений, размера provenance и decimal сохраняют конечный вычислительный бюджет. Конвертации валют и вывода численности из индивидуальных worklogs нет. Сценарные подмены полей не записывают источники и не маскируют прямые source-функции: их значения показываются как данные источника, а изменение производится формулой/обычным числовым полем сценария.

Сценарная подмена источника задаётся отдельно от field_key: `source`, product_id, необязательная точная team_id, месяц и значение. Источник сначала читается/фиксируется для базового расчёта и provenance; подмена меняет только результат сценария. Product/team должны совпадать точно. Частичное замещение агрегата всех продуктов/команд и применение общего значения к произвольной подкоманде отклоняются: численность не обязана быть аддитивной. В Explain сохраняются captured_value и overridden. Базовый и сценарный источники разделяют один cache+бюджет, не состояние фактов.

Для переноса исторических формул добавлены чистые bounded операции `div16(a,b)` (округление деления до16 знаков как старый движок) и `round_minor(a)` (RoundBank0). Они не создают зависимостей и не читают порты. Граница Explain:16384 единицы числа наблюдений плюс элементов provenance за расчёт; разных source+slice не более128.

Составной отчёт использует `WithFormulaSnapshot(ctx)` для общего cache источников между продуктами/показателями и external-клонами движка. Session ограничена одной операцией, синхронизирована mutex и разделена по исходным правам пользователя и идентичности провайдера сервиса. Смена Scope или другого сервиса не переиспользует чужой источник. Конкурентные обращения одного source+slice читают провайдер один раз; контекстная отмена проверяется до/после ожидания.

CRM-валюта проверяется также по стеку фактически вычисляемых формул: полученная RUB-выручка не может быть подписана как USD, включая вложенную либо уже memoized метрику и CompareVersions. Для линейного переноса многоместных min/max добавлены чистые bounded min_pair/max_pair; они не создают source/field dependencies.

Одинаковый field+эффективный filter в одном вычислителе читается один раз и использует неизменяемые факты; повторная ссылка не копирует те же строки в Explain того же показателя. Разные фильтры и сценарные подмены остаются различимыми. На расчёт допускается до500000 строк уникальных чтений полей. Отдельный бюджет сериализуемого Explain:50000 строк,4096 узлов,16384 единицы происхождения; составной отчёт и обе стороны сценария разделяют этот бюджет. При превышении либо неполном раскрытии глубже6 возвращается явная ошибка, без усечения данных. Scalar Value может вычислить вход, превышающий только выводной бюджет, не формируя большой ответ Explain.
