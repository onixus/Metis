# ADR0031 — агрегированные проекции прямых источников формул

Статус: принято для итерации28.

EC-09 требует worklogs, CRM revenue и headcount в формулах. Текущая CRM-аналитика читает внешний порт непосредственно, сохраняемой полной финансовой проекции сделок нет. Сигналы содержат лишь сделки с feature requests и не могут служить источником всей выручки.

Приложение собирает полный снимок через публичные порты и публикует агрегированные значения с продуктом, месяцем и при необходимости командой. Типизированный app-адаптер обновляет проекцию по требованию для открытого периода; движок получает сохранённый агрегат и не строит URL или SQL. Выручка считается по won и ClosedDate, приписывается только primary ProductKey, дополнительные Products — attach metadata. Непривязанная/неоднозначная денежная won-сделка отменяет весь снимок, отсутствие сделок в полном снимке даёт настоящий ноль. Валютная конверсия отсутствует.

Worklogs сохраняются только агрегатом секунд по product/team и месяцам; стабильные IDs нужны при сборке для дедупликации и хеширования, но авторы/индивидуальные записи не публикуются в объяснении. Headcount приходит из месячной финансовой книги, повторные payroll-строки команды должны содержать согласованную численность, команды суммируются один раз. Численность продукта означает целую численность участвующих команд, а не FTE. Портфельный срез дедуплицирует одну и ту же команду по устойчивому team key и требует согласованного headcount во всех её строках; численность разных команд суммируется. Book/portfolio source universe задаётся явно METIS_FORMULA_BOOK_PRODUCT_ID; модельные UUID команды разрешаются через публичный Team.Key или стабильный UUID команды книги.

Отсутствующий, устаревший, неполный или конфликтующий снимок возвращает явную ошибку; ноль не используется как fallback. Периоды и обновления сохраняются вместе с аудитом на одной транзакционной границе. Закрытый период удерживает историческую проекцию и не обновляется неявно. Product и portfolio — разные ключи сохранения; portfolio требует доступа ко всем продуктам и не может быть прочитан как product-срез. Новых библиотек не требуется.

Уточнение исполнения после ревью итерации29: cache готового source+slice не обеспечивает согласованности разных срезов. Поэтому одна formula session дополнительно фиксирует полный raw CRM response, worklogs вместе с полной таблицей issue→product и author→team и финансовую книгу до проецирования срезов. Namespace включает identity приложения/провайдера и полный исходный Scope. Raw данные существуют только в памяти одной операции, не выдаются наружу; persisted snapshots остаются агрегированными. Загрузка callbacks вне cache mutex позволяет вложенные book/mapping captures, concurrent wait учитывает отмену; отдельная операция повторно читает живые порты. Ошибочный capture не заменяется нулём.

Полные raw captures дополнительно ограничены суммарно32MiB JSON-представления и128 namespace entries на операцию. Charge происходит до retaining clone; превышение и ошибка загрузки не удерживают даже partial payload. Waiters получают ту же ошибку либо отмену. Это отдельный ограничитель transient operation памяти; persisted aggregates не меняются.
