# ADR-0033: проверка новой книги через текущую общую модель

Статус: принято, итерация29; уточняет ADR0029 (EC-08/09/10/11/13).

## Контекст

После binding сохранённые локальные DSL-формулы являются историческими определениями. Их исполнение перед общим evaluator блокировало допустимые новые входы, даже когда общий registry уже содержал исправленную формулу.

## Решение

Текущая bound книга рассчитывает локально только входы и стандартные денежные агрегаты. Структура всех полей/ссылок, типы, границы денег, аллокации и calculation budget по-прежнему проверяются; локальные calculated значения не подменяются нулями. Common registry вычисляет активные custom metrics. Архивные ORIGINAL версии (не выше последней версии в HistoryArchive), ставшие историческими, исполняют исходную DSL. Текущая original версия уже использует common registry. Все созданные после binding версии используют common registry даже при явном выборе версии: закрепляются входы, а формула выбирается из действующей на период общей истории. Это новый расчёт pinned-входов, а не сохранённый immutable report result; после закрытия периода общие определения защищены существующим запретом ретроспективных правок.

До append Save создаёт закрытое внутри economics context представление одного candidate snapshot, повторно проверяет текущие общие показатели на нём через обычные публичные порты и запрещает append при ошибке. Context не меняет Scope: чтение candidate требует исходных finance/product прав. Данные хранилища не подменяются и не записываются до проверки; исходные snapshots immutable. В PostgreSQL capture/audit и append продолжают участвовать в общей транзакции application operation.

## Последствия

Исправленная общая формула позволяет сохранять новые входы без устаревшего DSL. Ошибки текущих формул запрещают новую версию книги. Нет новых зависимостей, миграций или HTTP-контрактов; candidate context не экспортируется и живёт только во время Save.
