# ADR-0035: принадлежность рёбер и атомарные ограничения контракта

Статус: принято, исправления review PR60 (PG-03/04/08, AD-02, NF-S01).

## Контекст

contract_id сам по себе не доказывает принадлежность ребра. Старые API/Store позволяли ассоциации с чужими сторонами. Удаление таких ассоциаций при редактировании контракта нарушало scope; замена реальных зависимостей не обновляла сохранённые implied dates.

## Решение

Общая проверка принадлежности требует contract_id, integration и направления consumer→provider с точными сторонами контракта и фактическим product_id обеих привязанных фич. Она применяется в Service.CreateLink, обоих Store.SaveLink, candidate graph, удалении из persistence/cache. Новые неверные ассоциации отклоняются. Старые неверные ассоциации сохраняются байт-в-байт и продолжают участвовать в графе; редактирование контракта не является правом на их очистку. Связи с nil contract_id остаются ручными.

Store.ReplaceContract возвращает изменённые Feature projections. Под единой блокировкой/транзакцией Store строит актуальный DAG из сохранённых фич/рёбер, заменяет только принадлежащие старому контракту рёбра, пересчитывает constraints старых/новых потребителей и downstream. Меняются только Affected/AffectedBy/ImpliedDate/UpdatedAt существующих фич. Произвольные feature updates от вызывающего кода не принимаются; scope не расширяется. Service применяет возвращённые проекции после успеха Store. Private fields, PlannedDate и внешние поля не изменяются.

## Последствия

Mem/PostgreSQL одинаково сохраняют legacy чужие ассоциации и не блокируют законное изменение контракта из-за scope чужого ребра. Отказ записи проекции откатывает контракт, рёбра и проекции. Удалённая зависимость перестаёт влиять на feature state/готовность контракта без дополнительного shift. Новых миграций/зависимостей/HTTP форматов нет.
