# Подключение Jira, Confluence и Bitrix24 коробки

Итерация 13, 2026-09-22. Поддерживаются контракты Jira Data Center REST v2/Agile 1.0,
Confluence Data Center REST и Bitrix24 REST в коробочной установке. Контрактные тесты
используют синтетические HTTP-серверы. Реальные установки, их версии, лицензии,
REST-модули, права сервисных пользователей и пользовательские поля не проверялись.
Для 1С ЗУП и 1С:Предприятие см. [профили источников](integrations-1c.md).

## Выбор источника

| Переменная | Значения | Назначение |
| --- | --- | --- |
| `METIS_DELIVERY_PROVIDER` | `none`, `jira` | Поставка и worklogs |
| `METIS_KNOWLEDGE_PROVIDER` | `none`, `confluence` | Страницы решений |
| `METIS_CRM_PROVIDER` | `none`, `csv`, `bitrix24` | CRM, только чтение |
| `METIS_DELIVERY_SYNC_INTERVAL` | Go duration, по умолчанию `1h` | Сверка эпиков и спринтов |
| `METIS_CRM_SYNC_INTERVAL` | Go duration, по умолчанию `1h` | Импорт сигналов CRM |

`none` явно выключает адаптер даже при оставшемся URL. При пустом provider сохранена
совместимость: Jira/Confluence включаются по соответствующему URL, CRM CSV — по
`METIS_CRM_DIR`, Bitrix24 — по URL. При двух настроенных CRM нужен явный выбор.
Неизвестный provider и неполная конфигурация останавливают запуск. Настройки должны
совпадать у API и worker; периодические задания работают в worker сразу после старта.
Секреты передаются через окружение из хранилища секретов; в JSON-маппингах их нет.
В production используйте HTTPS с доверенной цепочкой сертификатов. Redirect адаптеры
не выполняют; конечный URL должен быть настроен сразу.

## Jira Data Center

`METIS_JIRA_BASE_URL` — адрес установки, при необходимости с context path.
`METIS_JIRA_TOKEN` — сервисный PAT из хранилища секретов.
`METIS_JIRA_FIELDS_FILE` — необязательный путь к JSON (до 64 KiB); пример:

```json
{
  "epic_issue_type": "Epic",
  "epic_link_field": "customfield_12000",
  "epic_name_field": "customfield_12001",
  "feature_ref_field": "customfield_12002",
  "feature_label_prefix": "metis-feature-",
  "max_results": 100
}
```

Номера полей в примере синтетические. Укажите реальные идентификаторы установки.
Без файла Epic Link ищется по имени `Epic Link`, Epic Name — `customfield_10011`;
ссылка на фичу записывается меткой `metis-feature-<UUID>`. Если настроен
`feature_ref_field`, используется поле. JQL для `customfield_N` преобразуется в `cf[N]`.
Права сервисной учётной записи должны позволять чтение выбранных проектов,
эпиков, задач, досок, worklogs; создание эпика/приоритета/ссылки — только если эти
операции нужны. Внешние записи выполняются обработчиками outbox.

В разделе Delivery привяжите фичу к существующему эпику либо запросите создание
эпика; административная настройка задаёт доски для продуктов. Изменения полей
исходной Jira задаются deployment-файлом выше и применяются после перезапуска.
Поля проекции принадлежат трекеру и в UI не редактируются.

Webhook: `POST /api/v1/webhooks/delivery`, заголовок `X-Metis-Webhook-Token`,
значение берётся из отдельного `METIS_WEBHOOK_TOKEN`. Старый `/api/v1/webhooks/jira`
остаётся alias только для Jira. Без секрета маршрут выключен. Максимум тела 1 MiB.
Токен OIDC пользователя и PAT трекера не используются как webhook credential.

Worklogs читаются через `GET /rest/api/2/issue/{key}/worklog` со всеми страницами.
Порт возвращает внешние ID, непрозрачные ключи авторов, время UTC и duration без
округления. Фильтр — `Started >= since`; для месяца потребитель дополнительно
ограничивает `Started < until`. Это полный текущий снимок, который необходимо
заменять при повторном импорте, чтобы учитывать исправления и удаления. Индивидуальные
авторы не передаются в финансовые отчёты: перед распределением нужна явная таблица
`author key → team` и агрегация команда × продукт. Дисплейные имена/email не импортируются.
Пределы: 200 страниц на список, 10 000 worklogs на вызов. Неполная/повторяющаяся
пагинация, отрицательное или переполняющее время отклоняются целиком.

## Confluence Data Center

Настройте `METIS_CONFLUENCE_BASE_URL`, `METIS_CONFLUENCE_TOKEN` и
`METIS_CONFLUENCE_SPACE` (по умолчанию `METIS`). У сервисной учётной записи нужны
чтение и создание страниц в выбранном пространстве, labels и content properties.

Публикация решения передаёт постоянный `IdempotencyKey` — UUID решения.
Внешний заголовок страницы — `Metis <UUID>`; читаемое название решения остаётся
в содержимом. Перед созданием адаптер выполняет точный поиск по title/space через
`GET /rest/api/content`, затем проверяет маркер `Metis request: <UUID>` в storage body.
Чужая страница с тем же заголовком вызывает конфликт. Маркер создаётся вместе с
самой страницей; потеря ответа, откат локальной транзакции и повторный запуск клиента
не требуют сохранённого PageID для восстановления. Labels/properties повторяются,
событие завершения публикуется только после их успешного применения.

Это reconciliation, а не серверная гарантия exactly-once. Не переименовывайте
служебный заголовок и не удаляйте маркер до успешной публикации. При внешнем
переименовании/удалении, задержке видимости или нестандартной семантике уникальности
title возможна ручная сверка; вопрос 29 не считается полностью закрытым. Синтетические
contract tests покрывают потерянный ответ, сбой labels/properties и новый клиент.
Статический Compose mock позволяет обычную публикацию, но не моделирует хранилище
удалённой системы; проверка повторов находится в stateful Go tests.

## Bitrix24: коробочная установка

Используется REST-модуль установленной коробки, методы `crm.company.list` и
`crm.deal.list`. Это POST-запросы чтения: адаптер не вызывает методы записи в CRM.
`METIS_BITRIX_BASE_URL` — origin коробки либо origin с `/rest`, например
`https://crm.example.test/rest`. URL входящего webhook с идентификатором/секретом
в пути не поддерживается. `METIS_BITRIX_TOKEN` — OAuth access token; он передаётся
как `auth` в JSON-теле запроса, не в URL. Обновление и ротация токена выполняются
внешним механизмом учётных данных; автоматический OAuth refresh в пилоте отсутствует.

`METIS_BITRIX_FIELDS_FILE` обязателен. Файл задаёт соответствие полей установки
нейтральной модели; пример без секретов:

```json
{
  "accounts": {"segment": "INDUSTRY"},
  "deals": {
    "product_key": "UF_CRM_METIS_PRODUCT",
    "requested_features": "UF_CRM_METIS_REQUESTS",
    "blocks_on_features": "UF_CRM_METIS_BLOCKS",
    "version": "UF_CRM_METIS_VERSION"
  },
  "currency_scale": {"RUB": 2, "USD": 2, "EUR": 2}
}
```

Имена `UF_CRM_METIS_*` синтетические: создайте или сопоставьте реальные поля.
`product_key` должен совпадать с ключом продукта Метиды. Стандартные поля по
умолчанию: компании `ID/TITLE/INDUSTRY`; сделки `ID/COMPANY_ID/TITLE/STAGE_ID`,
`OPPORTUNITY/CURRENCY_ID/CLOSEDATE/COMMENTS`. Годовая выручка компании не выводится
из суммы сделок: ARR импортируется только при явном mapping `arr` и `currency`.
`requested_features` принимает массив строк либо строку с `;`. Без запросов
содержимое `COMMENTS` используется как текст сигнала. Сделки с неизвестным продуктом
пропускаются сервисом, количество пропусков отражается в логах worker.

Денежные значения разбираются точно в minor units, без float и без округления
лишних знаков; шкала неизвестной валюты должна быть задана. Пагинация использует
серверный `next`, порядок ID, явный select. Лимиты: 200 страниц, 10 000 записей,
4 MiB на ответ, 32 MiB суммарно; ошибочный курсор, повтор ID и частичные данные
вызывают отказ всего чтения. Ответы ошибок, URL и OAuth token не включаются в ошибки.

Для проверки с отключёнными системами задайте три provider в `none`: ядро,
ручные формы и экономика продолжают работать. Локальные контрактные проверки:
`go test -race ./internal/adapters/bitrix ./internal/adapters/jira ./internal/adapters/confluence ./internal/app`.
