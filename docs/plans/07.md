# План итерации 07 — roadmap (RM-01…RM-03)

Требования: RM-01, RM-02, RM-03 (ТЗ 3.5); правила 2.4 (сдвиг срока распространяется — история дат по событию PG-08);
сценарий приёмки 7.7 п.5 и п.7; инварианты 1–3, 7, 9, 10.

## Состав

1. `internal/roadmap/model.go` — сущности:
   `RoadmapItem` (ID, ProductID, FeatureID?, Title, Bucket now|next|later, StartDate/EndDate `kernel.Date`, ReleaseID?, Audience internal|sales_safe, Status),
   `Release` (ID, ProductID, Name, Version, PlannedDate, Status planned|released|eol),
   `DateChange` (ItemID, OldStart/OldEnd/NewStart/NewEnd, Reason, Actor, At, EventID для идемпотентности).
   Представления: `Timeline`, `NowNextLater`, `ByRelease`; sales-safe вариант `SalesSafeItem` без причин, статусов и истории.
2. `store.go` — `Store` + `MemStore` (элементы, релизы, история, обработанные события).
3. `service.go` — `Service`: CreateItem/UpdateItem/Items/Timeline/NowNextLater/ByRelease/ChangeDates/DateHistory/CreateRelease/Releases.
   Аудитория берётся только из `sc.Audience()`: для sales_safe отдаются только элементы `Audience=sales_safe` и урезанные типы; параметров «покажи internal» нет.
   ChangeDates требует непустую причину (`kernel.ErrValidation`).
   События `roadmap.item.saved`, `roadmap.dates.changed`, `roadmap.release.saved`.
4. `handler.go` — `ShiftHandler` (`kernel.Handler`) на `portfoliograph.EventDateShifted`: история для элементов источника и затронутых фич,
   сдвиг EndDate источника на new_date; идемпотентность по Event.ID; работает от сервисного Scope из конструктора.
5. ABAC: запись — `ActionWriteRoadmap(productID)`; чтение — `ActionReadStrategic(productID)`; нулевой Scope запрещает всё.
6. Тесты: `TestRM01_*`, `TestRM02_*`, `TestRM03_*`, отказ ABAC (PM VM не пишет roadmap EDR).

## Не входит

RM-04…RM-06 (этапы 2–3); состав фич и release notes релиза (RM-05); HTTP-обработчики, OpenAPI и миграции — в итерации httpapi/db.

## Критерий готовности

`gofmt`, `go vet`, `golangci-lint`, `go test -race ./internal/roadmap/...` зелёные.
