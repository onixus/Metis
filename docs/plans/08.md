# План итерации 08 — порт DeliveryTracker, адаптер Jira, delivery (DL-01…DL-03, AD-05, NF-R05, NF-R06)

Требования: DL-01, DL-02, DL-03 (ТЗ 3.8; DL-04/05 — этап 3, не делаем), AD-05 (3.12), порт DeliveryTracker (4.1),
правила коннекторов (4.2), производные данные Jira (4.4), NF-R05, NF-R06 (5.2), NF-S17 (5.3), сценарий приёмки 7.7 п.5;
инварианты 1–5, 9–11.

## Состав

1. `internal/ports/deliverytracker.go` — порт `DeliveryTracker` с нейтральными типами `Epic`, `Issue`, `Sprint`, `Version`,
   `Worklog` (этап 3 — только тип и метод), `WebhookEvent` (ExternalID для идемпотентности, Type, EpicKey, ChangedFields, NewDueDate).
   Чтение: эпики проекта, эпик по ключу, задачи эпика, спринты доски (цель, состав, состояние, даты), версии, worklogs.
   Запись: `CreateEpic`, `SetEpicPriority`, `LinkEpicToFeature`. Никакой Jira-специфики в именах.
2. `internal/adapters/jira` — клиент Jira Data Center REST v2 и Agile 1.0 на `net/http`:
   `Credentials` (токен из хранилища секретов, не логируется), `FieldConfig` (имена полей Epic Link / Epic Name / ссылка на фичу),
   `Epics` по JQL, `EpicIssues`, `Sprints` (+ состав спринта), `Versions`, `CreateEpic`, `SetEpicPriority`, `LinkEpicToFeature`,
   `ParseWebhook` (`jira:issue_updated` с changelog по `duedate`/`fixVersions`).
   NF-S17: строки из Jira — недоверенные: обрезка длины и удаление управляющих символов (`sanitize`).
   Коды ответов → `kernel.ErrForbidden`/`ErrNotFound`/`ErrValidation`/`ErrUnavailable`.
   Контрактные тесты `TestJiraAdapter_*` на синтетических ответах `fixtures/jira/*.json` через `httptest.Server`.
3. `deploy/compose/jira-mock/mappings/*.json` + `__files/*.json` — WireMock: поиск эпиков (в т.ч. «SOAR-42 Коннектор EDR v2»
   с due date), эпик по ключу со сценарием `epic-shift` (состояние `Shifted` → due date +21 день; переключается через
   `PUT /__admin/scenarios/epic-shift/state`), задачи эпика, создание эпика, спринты и их состав, версии;
   файл `webhook_epic_shifted.json` — тело webhook для e2e.
4. `internal/delivery` — проекция трекера и производные метрики:
   - `model.go`: `Mapping` (FeatureID→EpicKey), `ReleaseMapping` (ReleaseID→FixVersion), `EpicProjection` (поля Jira только на чтение,
     `InitialScope` — первый снимок состава), `SprintStatus` (цель, состав, done/total, carried over), `FeatureMetrics`
     (готовность, scope creep, план/факт), `SyncState{LastSuccessAt, LastError, Lag, Stale}`, `FieldMapping`, `ConnectorStatus`.
   - `store.go`: `Store` + `MemStore` (маппинги, проекции, спринты, состояние синхронизации, обработанные события).
   - `service.go`: `Service`: `MapFeature`, `MapRelease`, `CreateEpicForFeature` (только событие `delivery.epic.create_requested`
     через `kernel.Publisher` — инвариант 5), `FeatureProjection`, `FeatureMetrics`, `SprintStatuses`, `Sync`, `HandleWebhook`
     (идемпотентно по `ExternalID`; сдвиг due date → `portfolio.ShiftFeatureDate`), `ConnectorStatus`, `SetFieldMapping`.
   - `handler.go`: `NewCreateEpicHandler(tracker, svc, portfolio, sc)` — воркер: вызывает порт, привязывает ключ, пишет
     `ExternalKey` через `portfoliograph.UpdateFeature`; идемпотентен по `Event.ID`.
   - ABAC: проекция/метрики — `ActionReadPrivate(product_id)`; маппинг — `ActionWriteGraph`; коннектор — `ActionManageConnects`.
5. Тесты: `TestDL01_MappingAndEpicCreationGoesThroughOutbox`, `TestDL02_SprintStatus*`, `TestDL03_ReadinessScopeCreepPlanFact`,
   `TestAD05_ConnectorStatusRequiresAdmin`, `TestNFR05_StaleFlagWhenTrackerDown`, `TestNFR06_WebhookIdempotent`,
   `TestPG08_EpicShiftPropagatesToFeature`.

## Не входит

DL-04, DL-05 (этап 3); HTTP-обработчик webhook, OpenAPI, миграции и outbox-таблицы — в итерации httpapi/db; e2e-сценарий 7.7 п.5.

## Критерий готовности

`gofmt`, `go vet`, `golangci-lint`, `go test -race ./internal/delivery/... ./internal/adapters/jira/...` зелёные.
