# План итерации 11 — этап 2: discovery, решения, compliance

Постановка: ТЗ раздел 6, строка «2. Discovery, решения, compliance». Состав: адаптер Confluence (порт KnowledgeBase), DS-01…05, DA-01, CT-01…04, CM-01…07, RM-04, RM-05, PR-04, PR-05, SG-04, AD-03; индекс и Evidence. Критерий готовности: трек сертификации версии ведётся от гейтов SSDLC до сертификата; фича агента платформы управления показывает затронутый baseline продукта Server; ADR создаётся из шаблона со связями.

Долг этапа 1, закрываемый здесь: вопрос №12 — PG-хранилища signals, prioritization, roadmap, delivery.

## Волна 1 — домены (параллельно, без правок OpenAPI и app)

1. `internal/discovery` — DS-01…DS-04, SG-04, AD-03.
   - `Hypothesis` (product_id, статусы `draft|testing|confirmed|rejected`, допущения, критерий подтверждения, `FeatureID` опц.), `Interview` (аккаунт, сегмент, дата, участники), `Insight` (текст, привязки к интервью, гипотезам, сигналам), `Evidence` (источник, дата, уровень доверия `low|medium|high`, статус проверки `unverified|verified|rejected`, ссылка, `SHA256` опц., привязки).
   - Трассировка DS-04: `Trace(ctx, sc, kind, id)` — граф «сигнал → инсайт → гипотеза → фича → решение» в обе стороны; решения — через порт `DecisionLinks`.
   - SG-04: порт `Embedder`/`SimilarityIndex` (интерфейс в домене; реализация — pgvector в pgstore либо косинус в памяти); `SimilarSignals`, `MergeSignals` через порт `signals`.
   - AD-03: `CustomFieldDef` (сущность `feature|signal|hypothesis`, тип `string|number|date|enum`, обязательность), значения в `map[string]any`, валидация.
   - Привязка сигнала к гипотезе (`HypothesisID` в signals, вопрос №07 закрывается).
2. `internal/commitments` — CT-01…CT-04.
   - `Commitment` kind `customer|regulatory`; кому, что, срок, основание, владелец; для regulatory — подтип `certificate_expiry|support_end|vuln_fix_deadline`; привязки к фиче, релизу, продукту.
   - Реализует `portfoliograph.CommitmentChecker` (CT-03): обязательства, срок которых раньше implied_date затронутых фич.
   - Обработчик `roadmap.EventDatesChanged` / `portfoliograph.EventDateShifted` → `Alert` (append-only список алертов с причиной) и событие `commitments.alert.raised`.
   - CT-04: `EnsureRenewalItems` — за настраиваемый срок (по умолчанию 18 мес.) до `certificate_expiry` создаёт элемент roadmap через порт `RoadmapWriter`; идемпотентно по обязательству.
3. `internal/compliance` — CM-01…CM-07.
   - `RequirementSet` (код, версия, тип продукта, перечень требований) — версионируемый каталог (CM-01). Номера документов ФСТЭК/реестра не указываются (ТЗ 8.2) — синтетические коды.
   - `TrackTemplate` (тип продукта, упорядоченные `GateTemplate` с `Parallel` группами) (CM-02); `Track` привязан к продукту и версии (релизу), `Gate` (владелец, срок, затраты `kernel.Money`, чек-лист `ChecklistItem`, статус `pending|in_progress|passed|failed`) (CM-03).
   - `EvidenceItem` (ссылка, SHA-256, статус) в журнале `evidence_log` только INSERT со сцепкой хешей по образцу `audit` (CM-04).
   - `ReleaseReadiness(releaseID)` — «готов к сертификации» только при закрытых чек-листах гейтов SSDLC (CM-05); порт для roadmap.
   - `ImpactClass` фичи: `none|analysis_required|security_functions` с обоснованием и автором (CM-06).
   - `CertifiedBaseline` (продукт, версия, набор требований, дата сертификата, EOL); `AffectedBaselines(featureID)` по связям `bundled` и `shared_component` через порт графа (CM-07).
4. `internal/roadmap` RM-04, RM-05; `internal/prioritization` PR-04, PR-05.
   - RM-04: `Branch` `certified|evolving` у релиза; в сертифицированной ветке разрешены только элементы вида `fix`.
   - RM-05: состав фич релиза, release notes, матрица совместимости из контрактов (порт `ContractReader`), дата EOL; статус `ready_for_certification` через порт `ReadinessChecker` (CM-05).
   - PR-04: флаг `RegulatoryMandatory` — фича исключается из `Ranking`, выдаётся отдельным списком.
   - PR-05: `Cost(featureID) = DevCost + ConfirmationCost(class)` через порт `ImpactClassifier`; коэффициенты подтверждения в настройках; учитывается `Product.SSDLCCertified`.
5. `internal/ports/knowledgebase.go` + `internal/adapters/confluence` — порт KnowledgeBase (страницы из шаблонов, page properties, labels, метаданные для индекса), адаптер Confluence Data Center REST, контрактные тесты на фикстурах; `internal/decisions` — DA-01 `DecisionRecord` (контекст, снимок данных, варианты, выбор, ожидаемый эффект, дата ревизии, связи с гипотезами/фичами/сигналами), создание страницы ADR из шаблона через порт (DS-05 — discovery brief тем же механизмом).

## Волна 2 — интеграция

6. `api/openapi.yaml` + `internal/httpapi` + `internal/app`: маршруты всех новых модулей, обработчики outbox, seed-дополнения (трек SOAR, baseline Server, класс влияния фичи агента платформы управления), `tests/e2e` — сценарий приёмки этапа 2.
7. PG-хранилища: signals, prioritization, roadmap, delivery (вопрос №12) и новых модулей; sqlc + goose; pgvector-индекс для SG-04.
8. `web`: страницы discovery, обязательств, compliance-трека, решений; класс влияния на карточке фичи; ветки релиза.

## Инварианты и правила

Каждый метод сервиса принимает `authz.Scope`; чтение — `ActionReadPrivate`/`ActionReadStrategic`, запись — новые действия `ActionWriteDiscovery`, `ActionWriteCommitments`, `ActionWriteCompliance`, `ActionWriteDecisions` в `authz` (compliance пишет роль `compliance`, discovery — `pm`/`marketing`, decisions — `cpo`/`pm`). На каждое требование — тест с ID в имени; на каждую политику — тест отказа. Новые зависимости — только через ADR. Депгард: новые доменные пакеты добавлены в `domain-purity`.
