# План итерации 12 — этап 3: экономика и маркетинг

Требования ТЗ: EC-01…EC-13, DA-02, DA-04, DA-05, DA-06, DL-04, DL-05, RM-06, CM-08, CM-09, AD-06;
дашборды портфеля, P&L и compliance (DA-03, часть этапа 3).

Этап 3 ложится на модули этапа 2 (`compliance`, `commitments`, `decisions`, `discovery`): новые
требования дописываются в эти модули, а не дублируют их.

## Что дописывается в модули этапа 2

| Модуль | Что добавляется | Зачем |
| --- | --- | --- |
| `compliance` | состав компонентов `CertifiedBaseline`, поиск затронутых версий по уязвимому компоненту, автосбор доказательств из пайплайна, плановые затраты треков | CM-08, CM-09, EC-06, DA-02 |
| `commitments` | запуск регуляторного срока устранения уязвимости, идемпотентный по основанию | CM-08 → CT-02 |
| `decisions` | измеримая часть ожидаемого эффекта и ревизия решения | DA-06 |
| `roadmap` | уровень запуска и календарь запусков | RM-06 |
| `delivery` | прогноз Монте-Карло и списания времени как база распределения затрат | DL-04, DL-05 |

## Состав работ

1. **`internal/economics`** — ядро экономики.
   - `model.go`: Period, FinancialField (EC-08), Metric с формулой (EC-09), FieldVersion/MetricVersion
     с датой действия (EC-11), ImportBatch и DataVersion (EC-07), FactRow, AllocationRule (EC-02),
     BundleRule (EC-04), TeamShare (EC-12), Scenario (EC-13).
   - `formula/`: компиляция и вычисление формул на cel-go; собственные функции агрегатов по измерениям
     (`sum`, `avg`, `count` по продукту, команде, периоду, статье); лимит стоимости вычисления;
     произвольный код невозможен — среда без макросов расширения и без доступа к вводу-выводу (EC-09).
   - `graph.go`: граф зависимостей показателей, отказ в сохранении формулы с циклом, пересчёт только
     затронутых показателей, объяснение значения до исходных строк импорта (EC-10).
   - `pnl.go`: P&L продукта прямой и с нагрузкой хаба, P&L портфеля (EC-03), аллокация (EC-02),
     атрибуция бандлов (EC-04), инвестиции в фичу против выручки и стоимость старых веток (EC-05),
     экономика сертификации (EC-06), отчёты по двум осям и матрица «команда × продукт» (EC-12).
   - `service.go`: публичный интерфейс с `authz.Scope`; финансовые данные требуют `FinanceLevel`
     (NF-S02): `FinanceFull` — строки и формулы, `FinanceAggregates` — только итоги, `FinanceNone` — отказ.
     Просмотр и экспорт финансовых данных пишутся в аудит (AD-04).
   - `store.go`: `MemStore` по образцу этапа 1 (вопрос 12 — PG-хранилища отдельной итерацией).
2. **Порт `ports.FinanceImport` и адаптер `internal/adapters/financexlsx`** — импорт XLSX (EC-01, EC-07):
   шаблон маппинга листов и колонок на поля, предпросмотр, валидация, отчёт об ошибках по строкам,
   повторная загрузка периода создаёт новую версию данных, история загрузок. Загрузка по расписанию —
   периодическая задача воркера.
3. **`internal/delivery`** — DL-04: прогноз даты фичи методом Монте-Карло по throughput с доверительным
   интервалом (детерминированный источник случайности в тестах); DL-05: worklogs как база распределения
   затрат, выгрузка в economics через порт.
4. **`internal/roadmap`** — RM-06: уровень запуска (launch tier) элемента и календарь запусков
   для маркетинга; sales-safe срез уровня запуска не раскрывает внутренние поля.
5. **`internal/marketing`** — DA-04: win/loss по причинам и сегментам, фичи в выигранных сделках,
   attach rate. Источник — порт CRM; в `ports.Deal` добавляются причина и дата закрытия, признак выигрыша,
   перечень продуктов сделки (поля принадлежат CRM, только на чтение, инвариант 4).
6. **`internal/compliance` (модуль этапа 2)** — CM-08: по идентификатору уязвимого компонента список сертифицированных
   версий и запуск регуляторных сроков (создание обязательств CT-02 через событие);
   CM-09: порт `ports.SecurityPipeline` и автосбор доказательств (SAST, SCA, DAST, фаззинг, SBOM)
   в журнал доказательств со сцепкой хешей (CM-04, инвариант 8).
7. **`internal/decisions` (модуль этапа 2)** — DA-06: сравнение ожидаемого эффекта с фактом на дату ревизии;
   факт берётся из economics тем же движком формул.
8. **`internal/scenarios`** — DA-02: сценарии «что если» под capacity и бюджет; считаются движком формул
   economics с подменой входных значений, фактические данные не меняются; в результат входит влияние
   на обязательства (`commitments`) и треки сертификации (`compliance`).
9. **`internal/licensing`** — AD-06: ключ поставки со сроком действия и лимитами, подпись Ed25519,
   проверка офлайн; ограничение по лимитам проверяется при создании продуктов и пользователей.
10. **API и фронтенд**: разделы OpenAPI `economics`, `scenarios`, `marketing`, `analytics`, `admin`
    и новые операции compliance и decisions; страница «Портфель и P&L» в `web`
    (дашборд compliance сделан на этапе 2).
11. **Seed и приёмка**: финансовый контур референсных портфелей, тест `TestAcceptanceStage3` —
    P&L продукта в двух видах сходится с контрольным расчётом, сценарий показывает влияние
    на обязательства и треки (критерий готовности этапа 3 из ТЗ 6).

## Решения, требующие ADR

- ADR-0005: зависимости этапа 3 — `excelize` (BSD-3-Clause) для XLSX и `cel-go` (Apache-2.0) для формул;
  назначение, лицензия, сопровождение, ограничение стоимости вычисления.
- ADR-0006: лицензионный ключ поставки (AD-06) — формат, подпись Ed25519, офлайн-проверка, часы и льготный период.
- ADR-0007: аналитическое хранилище и BI. ТЗ называет ClickHouse с этапа 3 и Superset для DA-05.
  Решение итерации: аналитика остаётся на PostgreSQL, DA-05 реализуется как сохранённые определения
  дашбордов поверх API платформы; ClickHouse и Superset — отдельной поставкой по подтверждённому объёму данных.

## Тесты

На каждое требование — минимум один тест с ID в имени, например:
`TestEC07_ReimportCreatesNewDataVersion`, `TestEC10_RejectsFormulaCycle`, `TestEC09_NoArbitraryCode`,
`TestEC03_PnLDirectAndLoaded`, `TestEC11_ClosedPeriodNeedsExplicitRecalc`, `TestEC12_TeamProductMatrix`,
`TestDL04_MonteCarloConfidenceInterval`, `TestDL05_WorklogCostBase`, `TestRM06_LaunchCalendar`,
`TestDA04_WinLossBySegment`, `TestDA02_ScenarioDoesNotChangeFacts`, `TestDA06_ReviewComparesExpectedToFact`,
`TestCM08_VulnerableComponentStartsDeadlines`, `TestCM09_PipelineEvidenceAppendOnly`,
`TestAD06_LicenseExpiredRejected`. Каждая новая ABAC-политика — с тестом на отказ
(`TestEC03_ForbiddenWithoutFinanceLevel`).

## Критерий готовности

`go test ./...` с `-race` зелёный, включая `TestAcceptanceStage3`; `golangci-lint` без замечаний;
`npm run build` проходит; `api/openapi.yaml` и сгенерированный код обновлены; ADR-0005…0007 и
`docs/questions.md` дописаны.
