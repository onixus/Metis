# Итерация 13 — персистентные настройки compliance

## Контекст

Вопрос №25: `compliance.Settings` хранятся в памяти `compliance.Service`. На PostgreSQL-стенде изменённые параметры стоимости подтверждения, скидки сертифицированного процесса, срока baseline и SLA устранения уязвимостей теряются после рестарта.

## Требования

- CM-03 / PR-05: стоимость подтверждения и скидка должны переживать рестарт API.
- CM-08 / CT-02: регуляторные сроки устранения уязвимостей должны переживать рестарт API.
- Архитектурный инвариант: сервис работает только через публичный `compliance.Store`; PostgreSQL остаётся внутри адаптера `pgstore`.

## План

1. Расширить `compliance.Store` методами чтения и сохранения настроек.
2. Перенести источник истины из полей `Service` в Store.
3. Для `MemStore` хранить копию настроек с защитой mutex.
4. Добавить миграцию `compliance.settings` как singleton JSONB-запись.
5. Реализовать чтение/UPSERT в `pgstore`; отсутствие строки означает `DefaultSettings()`.
6. Добавить интеграционный тест персистентности.
7. Закрыть вопрос №25 в `docs/questions.md`.

## Проверка

- `make ci`
- `go test -tags=integration ./internal/compliance/pgstore/...`
