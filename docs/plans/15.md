# Итерация 15 — содержательные карточки Git-продуктов

Запрос владельца: заполнить карточки девяти добавленных репозиториев и определить
роль продукта/платформы по реальным связям. План до изменения кода.

PG-01/02/03/04/06/09, DA-03:
1. Изучить README, планы и код девяти локальных репозиториев; сохранить источники
   и ревизии. Различать реализацию, заявленные возможности и планы.
2. Добавить необязательное текстовое описание продукта в OpenAPI, домен, новую
   миграцию и UI. Старый клиент без поля не должен стирать описание.
3. Показать связи в карточке продукта. Не смешивать тип продукта с подтверждением
   промышленной готовности; плановые интеграции обозначать в контрактах.
4. Заполнить через штатный API описание, возможности, фичи с обоснованными статусами,
   источники и контракты/рёбра. Сохранить существующие UUID. Не придумывать владельцев,
   стоимость, даты, сертификацию и внешние SLA.
5. Проверить сохранение/валидацию/права описания, PG round-trip, web и браузер.
   Обновить стенд без удаления данных; проверить наполненность всех девяти карточек.

Заполнение стенда реальными названиями и содержанием репозиториев явно разрешено
пользователем; тестовые фикстуры по-прежнему синтетические. Сеть к GitHub и внешним
системам не используется. Исходные репозитории не изменяются.

## Результат

Обновлены девять существующих продуктов, добавлены 18 возможностей, 50 фич,
50 требований с источниками и 8 черновых контрактов (16 рёбер: продукты + фичи).
Повторная загрузка создала 0 сущностей. Исходные UUID и десять демонстрационных
продуктов сохранены. Манифест и основания классификации — `docs/portfolio/`.

Описание сохраняется через API и PostgreSQL, доступно при редактировании;
старый клиент без description не стирает его. Карточка показывает связанные продукты
и статус контракта без дублирования продуктового/фичевого ребра. Граф подписывает
статус контракта, включая черновые планы.

Проверки: Go race для portfoliograph и e2e; PG integration на отдельной БД;
golangci-lint без замечаний; web lint/typecheck/tests/build; повторная генерация
OpenAPI/sqlc без расхождений; gitleaks без находок. Новых зависимостей нет.
Браузером проверены описание APEX, его шесть связей и восемь фич, граф портфеля.
Стенд обновлён с новой миграцией без удаления данных.
