# Итерация 18 — обязательный Scope хранилищ (#18)

Дата: 2026-10-10. Требования: AD-02, NF-S01, NF-M01; инвариант 3.

## Цель

Прямой вызов хранилища не обходит авторизацию. Нулевой Scope запрещает операции,
продуктовые записи и чтения проверяют принадлежность, межпродуктовые связи — обе стороны.

## План до кода

1. Инвентаризировать Store, реализации в памяти/PostgreSQL, вызовы сервисов и worker.
2. Описать в ADR границу внутренней загрузки полного графа, глобальных настроек и
   служебных операций; сохранить действующие ограничения private/strategic/finance.
3. Добавить явный authz.Scope во все продуктовые Store и передавать Scope вызывающего.
   Проверять сохранённого владельца при upsert, запрещать перенос чужой записи по ID.
4. Реализовать одинаковые запреты в памяти/PostgreSQL и фильтрацию списков; сохранить
   транзакционные границы. Не выдавать сервисный Scope пользовательским операциям.
5. Добавить прямые отказные тесты AD02/NFS01 и архитектурный тест NFM01.
6. Проверить API/worker, race, PostgreSQL integration, lint, security/license gates;
   оформить один PR с фактическими результатами и статусом человеческого ревью.

## Приёмка

- Нулевой Scope, чужой продукт, подмена владельца, обе стороны контракта.
- Стратегический доступ не раскрывает приватные/финансовые данные.
- API/worker и внутренняя загрузка графа работают с явными полномочиями.
- Архитектурный тест отклоняет новые Store без Scope.

## Границы

HTTP-контракт и бизнес-роли не меняются; новые зависимости не планируются.
Существующий незакоммиченный docs/plans/17.md принадлежит предыдущей работе.
Issue остаётся открытой до полной проверки критериев; merge требует отдельной команды.

## Уточнение после проверок

Актуальный govulncheck обнаружил 13 вызываемых уязвимостей закреплённой
стандартной библиотеки Go 1.27.1 и x/net v0.58.0. Для прохождения существующего
security gate обновить Go до 1.27.2 и x/net до v0.60.0 — исправленных версий
из отчёта. Новые зависимости и исключения не добавлять; повторить проверки.

Финальная сверка границ: включить audit.Store, compliance.EvidenceStore и
outbox.Store в обязательный Scope и архитектурный тест без исключений.
Для общей цепочки/очереди требуется служебная роль, private ко всем продуктам
и внутренняя аудитория. Logger/Publisher/Worker создают внутренние полномочия;
пользовательские сервисы сохраняют свои проверки. Тестировать нулевой,
ограниченный служебный и обычный административный scope до обращения к БД.

## Реализация и локальная проверка

- Scope обязателен для всех Store, включая аудит, доказательства и outbox;
  архитектурный тест не содержит исключений.
- Mem/PG проверяют продукт, действие и сохранённого владельца; PostgreSQL
  запрещает смену владельца предикатом upsert, контракты проверяют обе стороны.
- Полный граф загружается внутренним scope; расчёт финансового агрегата сохраняет
  область продуктов. Коллекции MemStore отделены от входных и выходных значений.
- На исходном HEAD 7f0bd1a в отдельной копии воспроизведён прямой доступ к
  приватному сигналу без Scope. На исправлении отказные тесты проходят.
- После независимого агентского ревью устранены подавление ErrForbidden в
  delivery.MapFeature и изменение MemStore через общие ссылки на map/slice.
- На Go 1.27.1 с обновлёнными x/net-зависимостями прошли полный `go test -race
  -count=1 ./...`, полный PostgreSQL 16 integration с race, отдельный runtime
  API/worker с ограниченной ролью БД, vet и сборка без cgo.
- Web: lint, typecheck, 4 теста, build, генерация TypeScript прошли. OpenAPI Go/TS
  остались без diff; SQL перегенерирован sqlc. Новых HTTP-функций нет, браузерная
  приёмка в этой итерации не выполнялась.
- Go 1.27.2 закрепляется для исправления находок govulncheck; проверка этого
  toolchain и финальных security/license gates выполняется Linux CI PR.

Все изменения этой итерации написаны агентом. Человеческое ревью не выполнено.
