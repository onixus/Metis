# Итерация 19 — PostgreSQL для modeling (#26)

Дата: 2026-10-10. Требования: EC-07…12, NF-S02, NF-S16; зависимость #18 закрыта PR #53.

## План до кода

1. Сохранить существующую модель и HTTP-контракт; не объединять книги периодов с modeling (#34).
2. ADR-0012: отдельная схема modeling, добавляемые ревизии объектов, неизменяемые batches/facts и правила. Глобальные определения сохраняют полномочия ADR-0010.
3. Реализовать все Store-операции с обязательным Scope, sqlc и общим pgdb-контекстом. Проверять историю версий и отклонять устаревшую запись.
4. Подключить одинаковое хранилище API/worker. Импорт, ручной ввод и scheduled imports выполнять в транзакционной границе, включая аудит/outbox; конкурентные импорты сериализовать общей блокировкой приложения.
5. Проверить отдельные соединения/перезапуск, откат импорта, сохранение версий, финансовые отказы, малые команды и существующие расчёты.
6. Генерация, race, integration/runtime, lint, security/license gates и один PR. Все изменения агента; человеческое ревью не заявлять без факта.

## Границы

Новые зависимости, бизнес-роли и HTTP-функции не планируются. Незакоммиченный docs/plans/17.md сохранить вне этой итерации. API/worker acceptance проверяется на синтетических данных; новые редакторы и браузерный E2E относятся к другим issues.

## Уточнение NF-S16 до кода

У modeling нет достоверной численности команды; TeamCosts/Matrix раскрывают ФОТ даже для aggregates. До политики порога закрыть отчёты команд для нефинансовой роли (вопрос 46), сохранив продуктовый P&L. Это не реализация настраиваемого порога численности.

## Реализация и локальная проверка

- Добавлены схема modeling, sqlc-запросы и весь Store; история INSERT-only, Scope обязателен. Текущие facts выбираются одним SQL snapshot, чтобы конкурентный import не создавал пустой смешанный срез.
- API/worker используют одинаковое хранилище. Импорт/ручной ввод имеют доменный транзакционный порт; scheduler входит в общую границу приложения.
- Go 1.27.2: полный race, полный PostgreSQL 16 integration/runtime (роль metis_app), vet и сборка без cgo прошли. Линтер v2.14.0 с integration: 0 issues. Старый локальный линтер не поддерживает export format Go 1.27.2, поэтому установлен актуальный инструмент во временный каталог; проектные gates сохранены.
- Web lint/typecheck/4 теста/build, Go/TypeScript генерация прошли; HTTP-артефакты без изменений, sqlc добавляет отдельный пакет. CI/Makefile проверяют и новый вложенный generated-каталог.
- govulncheck прошёл с прежним исключением ADR-0005. go-licenses прошёл с корректным GOROOT Go 1.27.2; новых зависимостей нет. Secret scan и CI коммита проверяются после фиксации изменений.
- Реальные внешние системы и браузерный E2E не проверялись; новая HTTP-функция не добавлялась. Все изменения написаны агентом, человеческое ревью не выполнено.
