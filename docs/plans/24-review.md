# Итерация 24 — независимая проверка границ «Экономики»

Дата: 2026-10-25. Основание: приоритет владельца «добить Экономику», EC-01…EC-13, DA-02, AD-04, NF-S01/NF-S16. Статический обзор выполнен параллельно реализации; это не подтверждение внешнего CI или интеграций.

## Подтверждённая база

- Конструктор `economics/modeling` уже выбирает PostgreSQL-store в postgres runtime (`internal/app/app.go`); историческое ограничение MemStore из плана 17 устранено. Есть интеграционные тесты сохранности, истории, конкурентных ревизий, объектов и фактов.
- Книги периодов и modeling по-прежнему используют разные сервисы, источники фактов и движки; пользовательское объяснение различий и явный сверяемый перенос нужны для EC-03/08/09/13.
- Книги имеют строгие finance/full политики, целочисленные суммы и аудит с отказом при ошибке. Modeling отдельно допускает агрегированные отчёты; сырьё и матрица команд ограничены. Смешивать эти политики нельзя.

## Проверки

1. Узкие Go unit/race тесты для изменённых модулей; затем полный `go test -race ./...`, vet и golangci-lint.
2. Для PG-путей запустить `-tags integration` с реальной PostgreSQL 16/pgvector; отдельный runtime test использует приложение с прикладной ролью и отдельным worker. Пропущенный тест не считать подтверждением.
3. Frontend lint/typecheck/test/build, генерация OpenAPI, сравнение generated, лицензии.
4. Браузер: finance/full → импорт → конструктор → вычисление/пояснение/история → закрытие; aggregate/non-finance → прямые отказы сырого API; мобильный экран, обе темы и смена сессии.
5. Security checks не отключать. Доступные локально Go, golangci-lint и Docker; govulncheck, gitleaks и psql не найдены в PATH при обзоре. Сеть ограничена реестрами пакетов, поэтому удалённый CI/PR не запускался этим review.

NF-L01: обзор выполнен агентом Codex; человеческое ревью не выполнено. Итоговые изменения и результаты в основном плане итерации 24 имеют приоритет над этим исходным списком.

## Уточнение задачи перед реализацией

Родительский агент поручил ограниченное исправление DA-02/EC-13: проверка валют бюджетного сценария и затрат треков в `modeling/scenario.go`, регрессии без изменений контрактов API. Ненулевая сумма требует валюту конфигурации модели; отсутствующая пустая нулевая сумма сохраняет обратную совместимость. Проверяем сохранённые сценарии повторно при расчёте. Проверяем действующую версию денежного поля бюджета, если поле определено. Конвертация и точная семантика обязательств не добавляются.

## Дополнение до исправления аудита

По поручению основного агента проверяем все финансовые чтения modeling: Value, Explain, CompareVersions, Facts, продуктовый/портфельный P&L, TeamCosts/Matrix, FeatureEconomics/BranchCosts/CertificationEconomics, сценарий и историю импорта. Ошибка аудитора должна вернуть пустой результат и исходную обёрнутую ошибку. Добавляем пропущенные события чтения для команды/фич/веток/истории. Это не изменение пользовательских прав и не обещание транзакционного отката прежних write-путей.

## Дополнение до ручного ввода

Родительский агент добавляет HTTP ручного ввода. До его подключения проверяем `SetManualValue`: обязательный продукт и месяц, действующая на начало месяца версия поля, ручной источник и числовой тип; денежные значения — целые минорные единицы int64 в валюте модели. Ограничиваем показатель степени и размер коэффициента десятичного числа до любых преобразований, затем длину представления 512 байт. Даты/справочники не принимаются через числовой endpoint; объявления полей остаются совместимыми.

- Проверены валюты новых и исторических сценариев, действующее поле бюджета и затраты треков; ADR-0022. Пустая нулевая сумма совместима.
- Все перечисленные финансовые чтения возвращают ошибку при недоступном аудиторе; добавлены события для команды, фичи, веток и истории импорта. Записи старых путей ClosePeriod/Recalculate/правил по-прежнему требуют отдельной транзакционной унификации; этот результат не заявляет её завершение.
- Числовой ручной ввод проверяет действующую версию, источник, тип, валюту, int64 и ограниченный decimal. Поля date/reference можно объявлять, но этот endpoint не записывает их значения.
- Полный `CGO_ENABLED=1 go test -race ./internal/economics/modeling -count=1` — PASS после исправлений; `golangci-lint run ./internal/economics/modeling/...` — 0 issues. Для локальных Go-кешей использован writable `/private/tmp`.

## Дополнение до write-аудита

Продолжение по поручению основного агента: убираем последние игнорирования audit error в ClosePeriod/Recalculate/SaveAllocationRule/SaveBundleRule. Публичные методы используют уже существующий TransactionalStore, чтобы проверка, неизменяемая запись, аудит и outbox находились в общей scoped PostgreSQL-транзакции даже при прямом вызове сервиса. Добавляем отказные unit-тесты и PG-регрессию rollback. Memory-хранилище не является транзакционным; ему не приписывается persistent rollback.

### Результат продолжения write-аудита

Оставшиеся игнорирования ошибок удалены: ClosePeriod, Recalculate закрытого периода, SaveAllocationRule и SaveBundleRule возвращают ошибку аудитора. Для PostgreSQL публичные операции охватывают запись/аудит/outbox существующим scoped TransactionalStore. Добавлены AD04/EC02/EC04/EC11 отказные unit-тесты и PostgreSQL-регрессия сохранности после отказа. Полный modeling race PASS повторно; integration-пакет с новым тестом скомпилирован (`-tags integration -run '^$'`), реальный rollback должен подтверждаться прогоном с БД основным агентом. Предыдущее замечание об игнорировании write-audit относится к исходному состоянию и устранено этим продолжением.

## Дополнение до EC-10 lineage

Исправляем объяснение агрегатов до включения расчёта книги: статические ссылки формулы не содержат фильтры sum/count/avg и условные ветки. ### Результат EC-10 lineage

Explain теперь записывает и раскрывает фактически выполненные запросы поля с тем же фильтром продукта/команды/периода/статьи, что вычислитель; также отражает только исполненные ветки и вложенные показатели. ## Дополнение до типизированного моста

Проекция книги переносит numeric-type вместе с каждым фактом; категории — money. Приложение передаёт карту типов с теми же alias ключами в EvaluateExternal. Эффективный тип каждого реально определённого входного поля должен совпадать с типом модели точно (money/number/percent); нечисловые ссылки запрещаются. Отсутствующий в книге вход остаётся нулём из изолированного пространства, как в существующем контракте. Смысловой конфликт существующего числового поля не конвертируется молча.

## Дополнение до review mutex аудита

Сериализация Go ограничивается memory-store и принадлежит самому MemStore, чтобы два Logger одного хранилища согласованно назначали seq/hash. PostgreSQL сохраняет существующий протокол общей транзакционной блокировки приложения; Go-mutex не удерживается при ожидании его INSERT и не заявляется механизмом межпроцессной целостности. Регрессия: 64 конкурентных append через два logger к одному memory-store.

### Результат заключительного review

- Типы money/number/percent передаются из книги; effective-type mismatch отклоняется, включая end-to-end book number → model money. Целевой race по bridge/model/app PASS.
- Go-lock аудита теперь принадлежит MemStore и разделяется двумя Logger; PG не использует этот mutex. Audit/modeling race PASS.
- На подготовленной основной сессией PostgreSQL 16 (локальный loopback) реально выполнены с `-race -tags integration` `TestEC07_EC11_PostgresImportRollbackAndManualRollback` и `TestAD04_EC02_EC04_EC11_PostgresRuleAndCloseAuditRollback` — PASS. Ручная rollback-фикстура обновлена обязательным синтетическим product_id, чтобы проверять аудит, а не раннюю валидацию.
- Review UI выявил гонку между pending preview и изменением файла/маппинга/preserve_rules; передано UI-агенту для исправления. Исправление/браузерное доказательство фиксирует основной план.

## Дополнение до ограничения входов сценария

До публичного сохранения/расчёта сценария валидируем также исторические overrides: ограниченный decimal (как ручной ввод), действующая числовая версия импортного/ручного поля; денежный override — int64 в валюте модели. Источник calculated/date/reference не является входом. Один месяц сценария; продукты override входят в выбранный набор, если набор явно задан; все продукты проходят Scope. Пересекающиеся wildcard/точечные overrides одного поля запрещаются, чтобы порядок массива не менял результат. Ограничения: 128 overrides, 10 000 явно перечисленных продуктов и 64 вычисляемых метрики за вызов; эти границы предотвращают неконтролируемое расширение работы и не являются нагрузочной приёмкой.

### Результат ограничений сценария

Новые и исторические overrides проверяются до арифметики/сохранения; регрессии huge exponent, неподдерживаемых типов/источников, денежного переполнения, другого продукта/периода и пересечения wildcard проходят. Фактический P&L после допустимого сценария остаётся прежним. Полный modeling race PASS (11.6 s), lint 0 issues. HTTP-границы до decimal-парсинга и OpenAPI ограничения координируются основным агентом.

## Дополнение до ограниченной decimal-арифметики формул

Формулы d(string) и агрегаты должны проверять decimal до rescale/операции, поскольку CEL cost не измеряет внутреннюю big.Int-работу. Ввод/результат: ±512 exponent, ≤1700 coefficient bits, ≤512 символов развёрнутого числа; строка d — ≤512 байт до parse. Максимум текста формулы 8192 байта, максимум входов одного агрегата 500 000. Проверки применяются к результату каждой decimal операции и к источнику до суммирования/lineage. Сохраняются точные значения >2^53, без float-конвертации. Новые пороги и тесты фиксируются ADR-0027.

### Результат decimal-hardening

Полный `-race ./internal/economics/modeling/...` PASS после ограничения формул, включая формульные тесты огромной exponent, превышения результата multiply/rescale, всех агрегатов/вложенных метрик и exact integer >2^53; golangci-lint 0 issues. Отказной audit unit-fixture задаёт дату правил после закрытого месяца, чтобы при новой защите закрытых определений продолжать проверять отказ аудитора. Работа подзадачи завершена, дополнительные расширения не выполняются.
