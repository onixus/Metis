# Итерация 24 — визуальный конструктор экономики

Основание: запрос завершить «Экономику» первым приоритетом; EC-08, EC-09, EC-10, EC-11, NF-S02, задача #43.

1. Использовать существующие OpenAPI endpoints конструктора и сгенерированные типы. Отдельная вкладка модели явно отделяет определения модели от правил книги периода (ADR-0009); API и политики доступа не меняются.
2. Добавить формы финансовых полей (тип, источник, валюта, измерения, дата действия) и показателей (формула, дата действия), редактирование через создание версии, историю с автором и датой.
3. Для выбранного продукта и месяца выполнять расчёт с объяснением до исходных строк; сравнивать две версии формулы. Значения decimal остаются строками.
4. Проверять ошибки сохранения/расчёта, очищать результаты при смене среза и версии. Сетевые вызовы используют общий авторизованный клиент.
5. Добавить ID-регрессии преобразования истории в форму и выбора версий без потери десятичной точности; выполнить lint/typecheck/test/build.

Авторство: Codex; ручная приёмка человеком pending. Новых зависимостей нет. Полная приёмка EC-08…11 требует backend/PostgreSQL/runtime проверок отдельно.

Дополнение после проверки доступности сценария: добавлен ввод точных числовых ручных значений выбранного продукта/месяца с командой и статьёй через новый API. Деньги вводятся целыми минорными единицами; десятичные данные и результаты формул не переводятся в JavaScript Number. Область глобального конструктора явно требует all-products scope. Данные отдельных книг доступны через общий расчёт формулы в P&L (реализация родительского агента).

Браузерная регрессия: `web/scripts/acceptance-economics.cjs` использует настоящий loopback API/синтетические данные и проверяет ручной ввод >2^53, объяснение, новую версию/сравнение формулы, отклонение цикла, повторный импорт со сверкой и общую формулу на версии книги. Проверка dark/light и ширины 1440/390; ответы API не подменяются.

Дополнение DA-02/EC-13: после согласования точного влияния на обязательства добавляется вкладка сохраняемых сценариев бюджета/capacity. Используются существующие сценарные endpoint и новые typed поля влияния. Сценарий ограничен выбранными продуктом и месяцем, входы конструктора явно отделены от книги. Подмена числовых полей — decimal string, дельта бюджета — подписанные безопасные целые минорные единицы. UI показывает базовые/сценарные результаты и неизвестный срок отдельно от нарушения; факты не изменяет.

Результат: **PASS** lint/typecheck/build, 16 Node tests; реальная браузерная приёмка dark/light, 1440/390. Найден и исправлен конфликт React keys двух соседних панелей после смены версии книги; runner проверяет единственность панели. Первый браузерный прогон также выявил конкурентный отказ аудит-цепочки memory backend — исправлен родительским агентом с регрессией параллельных чтений. Финальный повтор проходит целиком, доказательства в [24-acceptance](24-acceptance/README.md).

Исторический сценарий выбирает доступные поля по версии, действующей в конце выбранного месяца; будущая смена типа/источника не скрывает прежние ручные поля. Проверка EC11_EC13 добавлена.
