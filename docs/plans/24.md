# Итерация 24 — завершение пользовательских путей экономики

Дата: 2026-10-25. Приоритет владельца: «Экономика», работа с агентами.
Требования: EC-01/07/08/09/10/11/13, DA-02, AD-04, NF-S02.

## План до кода

1. Проверить актуальное состояние книг и modeling: PostgreSQL конструктора уже подключён; исторический план 17 не является текущим статусом.
2. Добавить явный режим повторного импорта с сохранением однозначно сопоставленных правил/ручных значений и финансовой сверкой до записи. Прежний режим API сохранить. Начать с OpenAPI, перегенерировать сервер, Go-клиент и TypeScript.
3. Раскрыть существующий сохраняемый конструктор через интерфейс: поля, формулы, версии, расчёт, объяснение, сравнение. Явно показывать источник данных модели.
4. Проверить сценарный бюджет и валюты, отсутствие изменения факта, отказы доступа и закрытый период.
5. Выполнить race, integration при доступной БД, web build/lint/typecheck, генерацию, security/license gates. Зафиксировать фактические результаты и остаток требований без неподтверждённого заявления полной готовности.

Распределение: агент backend — reconciliation домена; агент web — конструктор; агент review — сценарии/независимая проверка; основной агент — API, HTTP, интерфейс импорта и сквозная приёмка. Новых зависимостей и изменений применённых миграций не планируется. Незакоммиченный план 17 не изменять. Внешняя сеть — только реестры пакетов; публикация PR пока ограничена этим правилом.

NF-L01: изменения пишут агенты Codex; человеческое ревью ожидается.

## Расширение после проверки пользовательского пути

Включены общий read-through расчёт формул на неизменяемой версии книги (ADR-0023), ручной ввод числовых фактов через OpenAPI, fail-closed аудит чтения/записи modeling и точное раскрытие выполненных агрегатов. Реальная браузерная приёмка выявила конкуренцию append аудита memory и дублирующиеся React keys при смене версии; причины исправляются с регрессиями. В рамках DA-02 план дополнен заменой эвристического окна «сегодня + сдвиг» на сравнение привязанной плановой даты со сроком обязательства; отсутствие/неоднозначность плана показывается явно. UI сохраняемых сценариев дополняется после этого API-контракта.

Сохранность закрытого modeling обеспечена отказом ретроспективных изменений конфигурации; будущие версии разрешены, явный force-импорт остаётся отдельным действием.
