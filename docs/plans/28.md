## Уточнения после сквозной проверки

Ручной ввод опубликованных manual-полей после binding направляется в книгу, а не оставляется без пути записи. Прежние независимые batches за месяц не создаются. На исходных аллоцированных manual Values сохраняются соседние product/team/item группы; служебные нулевые строки не увеличиваются при каждом сохранении и не перераспределяются действием worklogs. Новые schema-проекции разрешает только закрытый app grant на одно проверенное общее определение; произвольный HTTP schema bypass запрещён. Непредставимая в текущем формате книги точность отклоняется без округления.

FactRow получает необязательный book_product_id. Если он есть, batch_id обозначает immutable snapshot ID книги, data_version — версию книги; без него это первоначальная modeling version. Явный DataVersion в запросе исторических model facts продолжает читать первоначальную историю; версии книги доступны собственным snapshot API и архивом объединения.

Все миграции добавлены отдельно: modeling00002 — новый append-only kind, modeling00003 — запрет старых независимых write-путей после binding, economics00002 — snapshot sources. Уже применённые миграции не переписываются. Откат приложения на бинарник, не знающий binding, не объявляется поддержанным бизнес-откатом; он может читать только старые оригинальные данные. Фактического deployment/rollback в работе нет.
