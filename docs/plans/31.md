## План до кода

1. Backend: исправить замещение автоматически построенных рёбер при редактировании контракта (PG-04/05/07/08), атомарно сохранять контракт и его рёбра в памяти/PostgreSQL; проверить coexistence ручных связей и обновление критичности. Исправить пересчёт коэффициентов параллельных рёбер PG-07. Добавить чтение capabilities/requirements с приватным scope (PG-02, AD-02); сначала OpenAPI, затем генерация.
2. Портфель: обзор доступных продуктов/хабов/связей независимо от финансового доступа. Иерархия Capability→Feature→Requirement с созданием и повторным чтением, выбор capability у фичи, детализация последствий сдвига дат. Роль хаба независима от типа продукта (PG-01/02/06/08/10).
3. Граф: форма связи без drag, явная проверка парных endpoints, отображение ошибок раскрытия фич и корректные handles после загрузки; фильтрация и переход из портфеля (PG-03/05/09).
4. Контракты: создание/редактирование с обеими сторонами, фичами, версией интерфейса, владельцем, статусом и матрицей совместимости; сервер остаётся источником разрешений и проверки циклов (PG-04/05). Приватные данные читаются только при имеющемся доступе.
5. Проверки: ID-регрессии домена/HTTP/UI, Go race, lint/vet/build, web lint/typecheck/tests/build, интеграция PostgreSQL по доступности, synthetic browser acceptance desktop/mobile/themes. Проверить генерацию и security/license gates доступными локальными средствами, записать фактические ограничения и локальное PR описание с NF-L01 attribution.

Работают основной Codex и три агента: backend graph, portfolio UI, graph UI. Человеческое ревью pending. Новые зависимости не планируются. Архитектурные решения вне ТЗ сначала оформляются ADR; неоднозначности — docs/questions.md.

## Дополнение до исправления PG-08 после review

Подтверждён дефект: сохранённый ImpliedDate использовался как вход нового расчёта, а перенос источника назад вообще не пересчитывал зависимые фичи. Пересчитать effective date всего DAG от поставщиков к потребителям только из актуальных PlannedDate, переопределив плановую дату источника. Для источника сохранить ограничения его собственных поставщиков; для downstream пересчитать/снять устаревшие предупреждения. Регрессии: supplier переносится раньше, source с более поздним upstream supplier переносится раньше, persisted reload. Прежний тест «раньше не затрагивает» заменить проверкой актуального пересчёта по PG-08 §2.4.
