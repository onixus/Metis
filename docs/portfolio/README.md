# Git-продукты в стенде

Срез 22.09.2026: девять локальных репозиториев, уже созданных в стенде. Названия,
назначение и границы сверены с README, актуальными обзорами и файлами реализации.
[Манифест](current-git-products.json) содержит ревизии, наличие незакоммиченных
изменений, описание, 50 фич с источниками и восемь интеграционных контрактов.
Это версия анализа локального рабочего дерева, а не непрерывный Git-коннектор.

## Роли

| Карточка | Классификация | Основание |
|---|---|---|
| APEX (unified-platform) | Объединяющая платформа, хаб | Потребляет шесть продуктов через разные по зрелости клиенты |
| Shapoclyack | Платформа Attack Surface/VM, хаб | Сканирование, активы, риск, remediation, приём и управление Lariska; источник для APEX |
| Metis | Управляющая платформа портфеля, хаб | Общие граф, спрос, roadmap, compliance и экономика; управление карточками не равно runtime-интеграции |
| Asmodeus | Продукт ИБ | Движок подписанных киберучений и проверяемого feedback |
| ГенаДека (Pulse) | Продукт ИБ | Сетевой сканер и монитор периметра |
| BSDM-Proxy | Продукт ИБ | SWG/proxy и политики доступа |
| Ferrum | Продукт ИБ | Kubernetes admission/runtime enforcement |
| Lariska | Агент-продукт ИБ | Инвентаризация и надёжная доставка снимков в Shapoclyack |
| EvaCal | Прикладной продукт | Оценка трудозатрат и документы; несколько модулей не делают его хабом портфеля |

Хабы назначены явно по архитектурной роли, а не по искусственно добавленным
входящим рёбрам. Направление графа: **потребитель → поставщик**.

## Связи и достоверность

- APEX → Asmodeus: реализация HTTP-клиента подтверждена.
- APEX → Shapoclyack, BSDM, EvaCal: HTTP-попытки и fallback; совместимость,
  авторизация и полный пользовательский сценарий требуют приёмки.
- APEX → Ferrum: HTTP health, но политики и счётчики клиента хранятся в памяти.
- APEX → Pulse: текущий `trigger_scan` имитирует результат; реальный вызов — задача.
- Shapoclyack → Lariska: потребление инвентаря, код отправителя/приёмника есть.
- Lariska → Shapoclyack: потребление управления/обновлений, отдельная пара фич.
  Этот цикл продуктов допустим: цикла зависимостей самих фич нет.

Все восемь контрактов имеют статус **черновик**: анализ исходников подтверждает
намерение/часть реализации, но не приёмку текущего соединения. Имена различают
«Код», «Частично» и «План». Не добавлены прямой APEX → Lariska, неподтверждённые
Asmodeus → Ferrum/BSDM/Lariska или Metis → Git-продукты как технические интеграции.
Демонстрационные connected/healthy в коде APEX не использованы как доказательство.

Статус фичи «выполнено» означает наличие реализации по указанному источнику;
это не новый прогон тестов чужого продукта и не обещание SLA. «Запланировано»
взято из незакрытых пунктов локальных roadmap; «исследование» — предложение этого
анализа. Не назначены вымышленные бюджеты, сроки, владельцы, сертификаты и
контрактные версии. Прежние десять демонстрационных продуктов не изменяются.
