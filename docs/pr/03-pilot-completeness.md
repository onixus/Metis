# Итерация 12: рабочий пилот управления B2B-продуктами ИБ

Платформа имела домены этапов 1–2, но пользователь не мог пройти основной путь PM через интерфейс, а отдельный PostgreSQL worker подтверждал события без обработки. Теперь можно создать/изменить фичу существующего продукта, принять и разобрать сигнал, задать оценку и включить фичу в roadmap; поставка содержит web и исполняющий доменные события worker.

## Реализация

- Общая сборка API/worker, явная маршрутизация уведомлений и retry/DLQ неизвестных событий; периодические tracker sync и certificate renewals; защищённый webhook без user Bearer.
- PostgreSQL граница операции объединяет доменные записи, аудит и outbox. Ответ API отдаётся после commit; после rollback/savepoint восстанавливается граф. Блокировка применяется до чтения графа, авторизации и claim очереди; ожидание HTTP-операции ограничено и реагирует на отмену.
- Настройки compliance сохраняются новой миграцией `00003_settings`; Map не передаётся вызывающему по ссылке; ошибки чтения не меняют цену на default.
- UI: создание/редактирование фич, приём/triage и история сигналов, RICE/WSJF и параметры оценки, редактор roadmap с полным набором полей. Кеши запросов/мутаций изолированы по сессиям.
- Web внутри Docker API, публичная runtime-конфигурация OIDC, локальный `dev-token`, отдельный `migrate`, Compose с ограниченной DB ролью; Helm и руководство эксплуатации. Node24 согласован с установленными build tools.
- CI дополнен runtime integration с отдельной БД, проверками generated Go/TS и тестами UI-логики. Новых runtime-зависимостей нет.

## Требования и границы заявления

Исправления затрагивают PG-02/05/08, SG-01/03/05, PR-01/05, RM-01/02/03, CT-03/04, CM-03/06, DL-01/03, AD-01/04, NF-R06, NF-S01/05, NF-O01, NF-M04. Каждое проверяемое поведение закреплено тестом с ID. Это не заявление о полном закрытии всех требований перечисленных модулей.

API-маршруты и модели OpenAPI не расширялись; сервер, Go-клиент, TS-клиент и sqlc регенерированы. Миграция additive и совместима с предыдущим релизом. Откат бинарников не удаляет таблицу настроек.

## Проверка

```sh
make ci
make web
make check-generated
METIS_TEST_DATABASE_URL=postgres://… \
METIS_RUNTIME_TEST_DATABASE_URL=postgres://… \
  make test-integration
make vuln licenses secrets
```

Runtime-БД отдельная от БД остальных integration tests; ей нужны owner для миграций и LOGIN `metis_app` с паролем тестового owner (только fixture). Приёмки выполняются и без seed/Atlassian, включая CPO → PM → presale и запрет чужому PM. Runtime fault injection проверяет отказ outbox/аудита, две API-реплики, конкурирующие обратные рёбра, отдельный worker и rollback savepoint.

Подтверждено локально 2026-09-22:

- Полный `go test -race -count=1 -tags integration ./...` с двумя PostgreSQL БД — PASS, включая атомарность, concurrency/cycle и отдельный worker. `go vet`, golangci-lint — без замечаний.
- Frontend lint/typecheck, 4 Node-теста сессий/денег и production build — PASS. Остаётся предупреждение размера основного JS chunk (~583 kB), без заявления о NF-P06.
- govulncheck — без уязвимостей; Go/npm license checks — PASS; gitleaks рабочей копии и истории — без утечек.
- Реальные Docker-образы API/web, worker и migrate собраны. Helm3.19 lint — PASS; OIDC/HMAC+ingress manifests отрендерены.
- Полный Compose HMAC: pgvector, два WireMock, одноразовый migrate, API и отдельный worker. Создание ADR через API → outbox → worker → Confluence mock успешно; page_id сохранился после restart. Runtime-соединения принадлежат metis_app; UPDATE/DELETE audit/evidence запрещены; DLQ=0 в проверенном сценарии.
- Native Safari, отдельное private окно, настоящий PG+SPA: продукт → фича → sales-safe roadmap; B2B-сигнал с 12 000 000,01 RUB и ARR 0,29 → triage → связь с фичей; RICE 10 × 2 × 0,8 / 4 = 4 с объяснением; смена CPO → presale в одной вкладке не раскрывает приватные строки/действия; неверный токен возвращает стабильную пустую форму входа без redirect-loop.

OIDC browser flow, промышленный restore/нагрузка и реальный Atlassian в этой проверке не подтверждены. GitHub Actions в этой сессии не запускались: сетевое правило репозитория разрешает только реестры пакетов, поэтому подготовлено локальное описание PR без публикации.

## Остаётся

Общий PostgreSQL lock — сознательное ограничение пилота, не подтверждение производительности и HA. Не закрыты Store scope старых модулей, полная Delivery API/UI, редактор контрактов, внешняя идемпотентность Confluence, экономика/маркетинг, реальные отечественные адаптеры, лицензирование поставки, backup/restore/SLO, LLM. Порядок и критерии — в [обзоре готовности](../reviews/2026-09-22-product-readiness.md); архитектура — ADR-0005/0006; неоднозначности — вопросы 30/31.
