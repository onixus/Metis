# feat: экономика и выбранные адаптеры

План: [итерация 13](../plans/13.md). Решение: [ADR-0007](../adr/0007-economics-and-selected-connectors.md).

Платформа получает финансовые версии периодов и подключение выбранных владельцем
источников: Jira, Confluence, Bitrix24 коробки и 1С ЗУП/1С:Предприятие. Для поставки
появляются реальные данные и формы вместо заглушки интерфейса.

## Адаптеры и Delivery

- Bitrix24: `crm.company.list`/`crm.deal.list`, OAuth `auth` в JSON-теле,
  явное сопоставление пользовательских полей, точные minor units, ограниченная
  пагинация/ответы. Методы записи в CRM отсутствуют.
- Jira: worklogs с внешним ID, opaque author key, UTC и точной длительностью;
  все страницы спринтов и их задач; настраиваемое поле связи с эпиком в JQL.
- Confluence: постоянный ключ решения, проверяемая идентичность страницы,
  восстановление создания при потере ответа и новом клиенте; повтор labels/properties
  до подтверждения и события завершения. Заголовок `Metis <UUID>` остаётся постоянным,
  читаемое название решения — в содержимом.
- Infrastructure factory выбирает Delivery/Knowledge/CRM provider, API и worker
  используют одинаковые порты; CRM импорт запускается при старте worker и по интервалу.
- Delivery UI показывает readiness/scope creep/plan-fact, спринты и свежесть данных;
  пользователь с правом записи привязывает фичу либо запрашивает создание эпика через
  outbox. Администратор назначает доски и видит состояние сверки/счётчик DLQ.
- [Инструкция подключений](../integrations.md), [1С](../integrations-1c.md),
  синтетические примеры настройки без секретов.

Требования этой части: DL-01…DL-03/05, SG-01…SG-03, DA-01, NF-R05/06,
NF-S04/17, NF-L03. AD-05 покрыт частично: source fields задаются deployment JSON;
редактирование статусов/полей исходного адаптера через административный API в этой
итерации не заявляется. Project в административной форме служит значением по умолчанию
для форм администратора; каждая привязка хранит собственный project.

## Экономика

Финансовый пользователь загружает CSV/XLSX, проверяет предпросмотр и сохраняет
неизменяемую версию месячной книги. Версия содержит исходные строки, доли распределения,
поля и ограниченные формулы. Доступны прямой/нагруженный P&L, команда × продукт,
инвестиции в фичи/ветки/сертификацию, сценарий одного продукта, сравнение версий и CSV.
Закрытие/пересчёт и CAS защищают период; аудируются чтение, экспорт и изменения.
Роль finance требует `finance=full` и доступа ко всем участникам книги.

Отдельные профили 1С ЗУП и 1С:Предприятия собираются полностью перед записью;
изменённые закрытые периоды и книги с ручными настройками отменяют автоматический
пакет, сохраняя прежние версии. Jira worklogs агрегируются по явной таблице автор→команда
до попадания в экономику. Формулы не исполняют произвольный код или формулы из XLSX.
Подробные рабочие границы: [экономика](../economics.md).
