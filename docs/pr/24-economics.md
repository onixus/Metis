# feat(economics): завершить импорт, конструктор и сохраняемые сценарии

Историческое локальное описание отдельной экономической итерации. Объединённая изолированная поставка и её финальная валидация описываются в [плане30](../plans/30.md); прежние ограничения/статус публикации ниже относятся ко времени этой итерации.

Финансовый пользователь может загрузить исправленный файл с сохранением однозначно сопоставленных долей/ручных значений, проверить финансовую сверку, создать поле/формулу/версию в интерфейсе и выполнить общую формулу на выбранной версии книги. Конструктор также получает ручной ввод числовых фактов и сохраняемые сценарии бюджета/capacity с базовыми и сценарными показателями.

Влияние на обязательства рассчитывается от реальной связанной плановой даты, с отдельными признаками прежнего/нового нарушения и явным unknown при недостатке данных. Факт, планы и алерты сценарий не изменяет. Общий расчёт книги изолирован от отдельных фактов модели, использует ту же аллокацию и CEL-движок, проверяет типы/валюты и раскрывает реальные источники агрегатов. Ретроспективные изменения конфигурации закрытых периодов запрещаются; исправление данных требует явного force-импорта.

Финансовые чтения/записи modeling теперь возвращают ошибку при отказе аудита; PostgreSQL откатывает изменение вместе с аудитом/outbox. Memory-аудит поддерживает конкурентные чтения через несколько Logger без ложных409. Входы сценариев и арифметика формул имеют конечные числовые ограничения.

Требования: EC-01/02/03/04/07/08/09/10/11/12/13, DA-02, AD-04, NF-S02/NF-S05. Это перечень затронутых частей, не заявление полной приёмки каждого требования. API начинается с OpenAPI; сервер/Go-клиент/TypeScript перегенерированы. Новых runtime/dev зависимостей и изменений применённых миграций нет. План: [24](../plans/24.md); решения: ADR-0018, 0022, 0023, 0025–0028; уточнения: questions50/52 и последующие записи итерации.

Проверка: `CGO_ENABLED=1 go test -race -count=1 ./...`; с изолированными PostgreSQL16 БД задать `METIS_TEST_DATABASE_URL` и `METIS_RUNTIME_TEST_DATABASE_URL`, выполнить тот же прогон с `-tags integration`; `golangci-lint run ./...`; `make generate`; `npm --prefix web run lint`, `typecheck`, `test`, `build`, `licenses`. Реальная браузерная приёмка и воспроизведение: [24-acceptance](../plans/24-acceptance/README.md). Фактический итог gate фиксируется в [плане](../plans/24.md).

Не выполнены автоматическая миграция/слияние двух исторических хранилищ, ручной ввод нечисловых фактов, прямые formula-порты платформенных CRM/worklogs/headcount, причинная модель capacity→duration, постоянный инкрементальный кеш, реальные корпоративные источники/OIDC и production deployment. Новые бизнес-поставщики и конвертация валют не добавлены. Отдельные roadmap/commitments/delivery изменения другого параллельного чата не относятся к этой итерации.
