# fix(economics): устранить три дефекта ревью объединённой модели

Историческое локальное описание отдельной экономической итерации. Объединённая изолированная поставка и её финальная валидация описываются в [плане30](../plans/30.md); прежние ограничения/статус публикации ниже относятся ко времени этой итерации.

Срезы прямых источников одного расчёта теперь проецируются из единого исходного ответа CRM/worklogs и одной версии книги/headcount. Повторное чтение меняющегося CRM больше не нарушает равенство total=sum(products). Operation cache изолирован по исходному Scope/provider, клонирует mutable данные, учитывает отмену/ошибки и ограничен128 ключами/32MiB; новая операция обновляет открытые источники.

После объединения текущие записи, отчёты, сценарии и проекции исполняют общие формулы без устаревшей custom DSL книги. До append общая модель проверяет candidate snapshot с исходными финансовыми правами. Старые ORIGINAL версии из архива, ставшие историческими, сохраняют DSL; postbinding версии закрепляют входы и используют действующие на период общие определения, что раскрывается lineage. Ошибка текущей формулы не создаёт новую версию; PostgreSQL откатывает audit/capture.

FeatureEconomics/BranchCosts сохраняют исходный Scope перед внутренним вычислительным scope. Полные финансовые права снова работают после binding; aggregate-only, нулевой Scope и недоступные продукты по-прежнему отклоняются.

Требования: EC-05/07/08/09/10/11/13, NF-S01/02/05. План29 и подпланы созданы до кода; ADR0033/question53 уточняют original/postbinding границу, ADR0031 уточняет общий raw capture. Новых миграций, зависимостей и HTTP/OpenAPI контрактов нет. Generated files вручную не менялись. Результат gate и регрессии: [план29](../plans/29.md), [доказательства](../plans/29-acceptance/README.md).
